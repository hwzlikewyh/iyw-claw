# IYW 图片分身生图平台选择设计

## 目标

调整 `iyw-image-workflows` 的 `fission-generate` 平台选择策略：默认只向一个平台下发，优先使用通道四；用户明确要求多平台比稿时，才向全部可用平台下发，并将通道四排在第一位。实时配置没有通道四时，回退到实时配置顺序中的第一个可用平台。

## 范围与架构

- `scripts/iyw_fission_core.py` 增加统一的平台选择逻辑。
  - 先按现有规则解析实时“分身”配置和内置平台模板。
  - 默认模式选择通道四；通道四缺失时选择实时配置顺序中的第一个已支持平台。
  - 比稿模式选择全部已支持平台，并将通道四置于首位；通道四缺失时保持实时配置顺序。
  - 继续拒绝重复平台、空配置和未内置参数的平台，避免静默发送未知请求。
- `scripts/iyw_commerce.py` 为 `fission-generate` 增加 `--compare-platforms` 开关，默认关闭，并把开关传入核心生成函数。
- dry-run 使用同一套选择策略，不访问实时配置；默认请求体只包含通道四模板，比稿请求体包含全部内置平台模板且通道四优先。
- `SKILL.md`、`references/fission-generation.md` 和 `agents/openai.yaml` 明确默认单平台、显式比稿开关、通道四优先和缺失回退规则。

## 数据流与错误处理

`fission-generate` 只接收提示词和比稿开关。CLI 读取实时配置后构造 `models` 数组，再向 batch 接口发起一次收费创建请求。默认模式只产生一个 task；比稿模式产生每个平台一个 task。创建超时或响应不确定时沿用现有规则，只查询已获得的 task ID，不自动重建。

若实时配置包含重复平台、空的可用平台，或包含 CLI 尚未支持的分身平台，创建前返回配置错误。通道四缺失本身不是错误，按上述回退规则继续执行。

## 验证

- 单元测试覆盖默认通道四、通道四缺失回退、比稿通道四置首、空/未知/重复配置校验。
- CLI 测试覆盖 `--compare-platforms` 默认值和 dry-run 请求体。
- 运行与改动直接相关的 fission、commerce 及 Skill 文档测试，并确认仓库无测试临时文件残留。
