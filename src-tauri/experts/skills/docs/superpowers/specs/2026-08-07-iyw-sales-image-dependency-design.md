# IYW 销售资料优先由图片工作流提供

## 目标

将 `iyw-sales-assistant-workflows` 中的展会报告、趋势主题、卖场图片、销售画册、爆款图案和 AI 图统一优先路由到 `iyw-image-workflows`。该来源结果不足时允许使用其他合规来源补足；销售 skill 负责编排、数量目标、来源记录、缺项记录和客户包交付。

## 设计

销售资料类型与图片 skill 能力的对应关系如下：

| 销售资料 | 首选来源能力 | 交付要求 |
| --- | --- | --- |
| `exhibition_report` 展会报告 | 报告检索 | 只统计实际下载或保存且带报告来源的文件 |
| `trend_theme` 趋势主题 | 趋势检索 | 只统计实际保存且带主题来源的内容或文件 |
| `retail_image` 卖场图片 | 图片检索 | 只统计实际保存的图片文件 |
| `catalog_image` 销售画册 | 销售画册检索 | 只统计实际保存的画册图片或文件 |
| `pattern_poster` 爆款图案 | 图案/IP 资料检索 | 只统计实际保存且带来源的图案或海报 |
| `ai_image` AI 图 | 图片 skill 的 `fission-generate` | 只统计成功结果，保留任务或生成参数来源 |

销售 skill 必须先调用图片 skill 已公开的 CLI 和固定别名，不得猜测接口路径、请求体或自行复刻接口。只有图片 skill 的真实可用文件未达到目标数量时，才可使用合规公开检索、其他图库或其他生图能力补足。补足资料必须保存真实来源或生成任务信息；图片 skill 内部仍按自身契约选择固定检索或生产入口。

图片/资料获取失败、无结果、下载失败或结果无法落为真实本地文件时，销售流程先尝试合规补足，再继续处理其他资料和公司，并在 `materials`/批次状态中记录剩余缺项；不得用 URL、空文件、快捷方式或未验证生成结果计数。

## 影响范围

- 更新销售 skill 主流程、操作参考、数据契约示例和 agent 默认提示词，明确首选来源、类型映射、补足条件和缺项行为。
- 新增销售 skill 文档契约测试，锁定六类资料必须先指向 `iyw-image-workflows`，并允许不足时合规补足。
- 不修改 `materials` 枚举、资料数量目标或图片 skill CLI 接口；主代理记录每类首选尝试，销售 CLI 再校验 type/alias/source、真实文件和补充资料凭证，防止直接调用 `batch-package` 绕过来源门禁。

## 验证

运行销售 skill 文档契约测试，并运行现有图片 skill 搜索与工具测试，确认文档变更没有破坏图片 skill 的固定路由约束。
