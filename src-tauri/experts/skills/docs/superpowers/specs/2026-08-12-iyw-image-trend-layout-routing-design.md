# IYW 图片趋势路由与成组版式设计

## 目标

完善 `iyw-image-workflows` 的图片生产决策：用户同时提供一张基准图片并指定趋势或主题时，优先使用系列延伸；系列延伸失败后只回退一次变款。用户要求宫格、联图或其他成组版式时，优先通过一次图片任务直接生成一张完整合成图，只有任务失败或结果明显不符合用户指定布局时，才拆分生成并在本地拼接。

## 路由规则

- 有一张已上传或已检测的基准图片，且用户指定趋势或主题：先执行 `tool extend`。
- `extend` 创建失败、任务失败或最终结果不满足用户要求时，允许执行一次 `tool variation`；不得继续循环重试或再次回退。
- 没有基准图片时，即使用户指定趋势或主题，也不调用必须带图片的 `extend`，纯文本请求继续使用 `fission-generate`。
- 用户明确指定其他专用动作时，专用动作仍高于上述趋势路由。
- 收费任务创建结果不确定时沿用现有规则，只查询原 task ID，不把超时直接视为失败并创建回退任务。

## 成组版式

- 适用于 `variation` 和 `extend` 的宫格、联图、阵列或其他用户明确指定的成组布局，不限定为 2×2。
- 首次请求保持单个工具任务和 `batchSize: 1`，在提示词中明确要求模型直接输出一张包含完整布局的合成图，不拆为多个并发任务。
- 只有任务明确失败，或可用视觉检查确认结果明显不符合用户指定布局时，才进入兜底。无法视觉检查时保留单任务结果并说明布局未验证，不得据此增加收费任务。
- 趋势或主题场景的完整布局尝试顺序为一次 `extend`、一次 `variation`；二者仍失败或布局不符后，才按用户要求生成各分图并执行本地拼接。
- 用户没有给出可确定的布局、顺序或分图数量时，不猜测行列和顺序，先向用户确认。

## 本地拼接命令

在 `scripts/iyw_commerce.py` 增加只读本地命令 `compose-layout`，不访问 API、不读取 token：

```powershell
uv run --project $skillDir --python 3.13 python $commerceCli `
  compose-layout --image "C:\path\1.png" --image "C:\path\2.png" `
  --rows 1 --columns 2 --out "C:\path\layout.png"
```

- `--image` 按用户指定顺序重复传入本地图片。
- `--rows` 和 `--columns` 必须为正整数，图片数量必须精确等于二者乘积。
- `--gap` 为非负像素，默认 `0`；`--background` 为 `#RRGGBB`，默认白色。
- 每个单元格采用所有输入图片中的最大宽高；图片保持宽高比缩放至单元格内并居中，不裁切、不拉伸。
- 输出仅允许 `.png`、`.jpg`、`.jpeg` 或 `.webp`。默认拒绝覆盖现有文件，只有显式 `--force` 才覆盖。
- 输入文件不存在、格式不支持、布局与数量不符、输出路径非法或解码失败时，在写文件前失败。

## 依赖与文档

- 在 `iyw-image-workflows/pyproject.toml` 增加 Pillow 依赖并更新 `uv.lock`。
- `SKILL.md` 只保留路由、单任务优先和何时读取详细参考的核心规则，详细 payload 和拼接命令写入 `references/commerce-operations.md`，避免主 Skill 超过 300 行。
- `agents/openai.yaml` 同步趋势路由、一次回退和成组版式单任务优先规则。

## 验证

- 文档契约测试覆盖：趋势或主题加基准图片优先 `extend`、无图仍走 `fission-generate`、失败只回退一次 `variation`、成组版式优先单任务以及无法视觉检查时不增加任务。
- 拼接单元测试覆盖 1×4、2×2、顺序、画布尺寸、比例保持、间距、图片数量不匹配、拒绝覆盖和输出格式。
- CLI 测试确认 `compose-layout` 不初始化网络客户端、不读取 token，并生成可重新打开的目标图片。
- 运行现有图片工具、分身、搜索和 Skill 校验；删除测试缓存和临时文件。
