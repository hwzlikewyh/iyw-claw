# 星河连接诊断

脚本版本 1.4.0：保留 Windows .NET HTTPS 检查和 curl 崩溃识别，并采集新版应用的模型连接诊断字段。无需升级电脑上的 curl。

模型目标主机/端口、代理策略、错误链类别、Windows 错误码和网关请求阶段由原助理代码记录；需要先运行包含诊断补丁的原助理。仅更新脚本无法让旧应用生成这些字段。`proxy_route_observed=false` 表示 HTTP 库没有暴露最终实际代理，代理策略及环境配置不能冒充最终代理路径。

在报错的那台 Windows 电脑上运行。适用于原助理进程内置的星河，无需安装 Codex CLI、Python 或额外模块。

1. 把整个压缩包解压；保持原助理打开，先复现一次连接失败。
2. 双击 `run.cmd`，无需管理员权限。脚本需要 Windows PowerShell 5.1；HTTP 检查使用系统自带的 `curl.exe`，缺失时会在报告中标明。
3. 云端 API 地址：正式版通常直接回车。默认值来自当前源码，是 `https://gateway.iyw.cn/iyw-fusion-api/v1`，不是从故障进程读取的最终配置；测试版或自定义部署请填写实际云端地址。不要填写带随机密钥路径的本机模型网关地址。
4. 代理地址：仅供对照，没有就回车。支持不带认证的 HTTP、HTTPS、SOCKS5、SOCKS5H 代理。脚本不会改变应用代理设置。
5. 日志位置：自动尝试从运行中的原助理安装位置找 `logs`，也尝试原日志里的 `D:\WXDrive\原助理\logs`。可以改填实际 logs 目录或导出的 `1.txt`；拖入路径带双引号也可以。
6. 等待约 30 秒至 3 分钟。把脚本所在目录新生成的 `xinghe-report-日期时间.txt` 发回分析。

报告包括：原助理进程版本和监听端口、DNS、TCP、无认证 GET 的 TLS/HTTP 结果、可选代理对照、最近日志摘要及初步判断。目录模式读取最新两个 `iyw-claw*.log` 的各 8000 行，保留最近 250 条匹配事件；较早故障请单独导出该时间段日志后指定文件。

Windows .NET 探测明确使用 TLS 1.2、直连、不携带凭据、不跟随跳转，并保持证书校验。TLS 设置仅在采集进程中临时使用并恢复；不修改系统配置。Windows 事件只输出 curl/原助理崩溃的时间、应用名、故障模块名/版本及异常码，不输出事件完整消息或文件路径。无法读取事件时记录状态，不要求提权。curl 的 `0xC0000005` 表示进程内存访问异常，不能当作网络超时。

日志使用字段白名单，保留时间、线程 ID、耗时、重试次数、错误类别及已知网关错误码；不输出原始 message/detail/reason、会话内容、运行时配置、认证头、密钥、用户名和文件路径。报告会包含用于网络定位的服务域名、IP 和端口；发送前可以自行查看。

脚本只读取信息并创建本地报告，不上传文件、不访问会话内容、不修改数据库/配置/代理/证书/防火墙、不调用收费模型。启动器的 ExecutionPolicy Bypass 只作用于此次 PowerShell 进程，不修改系统执行策略。

当前源码中，内置工具使用进程内通道；模型调用经过本机模型网关，再强制直连云端。故障电脑可能安装不同版本，不能仅凭当前源码推断现场路径。报告中的监听端口只是进程快照，不能自动确认哪个端口就是模型网关。未读取或探测随机密钥路径。

HTTP 401/403/404/405 只说明收到了 HTTP 响应。这里没有执行带认证的模型 POST、SSE 或内置工具调用，也没有关闭证书验证，因此报告不代表模型权限、流式响应和整个会话已经正常。

命令行运行示例（可选）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\diagnose-xinghe.ps1 -NonInteractive -LogPath 'D:\WXDrive\原助理\logs'
```

如果地址输入错误、输出目录不可写，窗口会显示错误类型。检查输入后重跑；不要关闭证书验证、全局关闭防火墙，或把 API Key 填入脚本。
