# Windows Agent 运行时性能改动

本改动降低 Agent 启动重复探测、终端输出复制和历史消息包装开销，并为星河、远山提前初始化运行时。Markdown、虚拟列表、消息组件与流式合批节奏保持原样。

## 2026-09-23 启动与请求等待修补

托管环境清单在进程内复用解析结果，每次仍检查提交事务；工具入口校验最多缓存
64 个规范路径。缓存命中同时匹配文件身份、长度、修改/变更时间和预期 SHA-256。
Windows 使用打开句柄的卷号、文件 ID 和 ChangeTime，Unix 使用设备、inode 和 ctime；
无法取得可靠身份时完整校验且不缓存。文件读取前后变化、清单变更或环境修复会使缓存失效，
失败结果不作为已验证结果复用。同一文件的并发哈希由独立锁合并。

终端环境准备去掉一次重复的工具目录处理，新增 `builtin_prompt_prepare` 和
`terminal_environment_prepare` 启动计时，以区分指令/工具发现和终端环境的耗时。

星河原生本地摘要与远程压缩的请求、重试及既有回退共享一次 300 秒等待预算。
网络预算只包裹请求阶段，摘要成功后的历史提交不在超时中途取消。
普通发送与压缩不再重试 HTTP 402 等不可恢复客户端错误；408、409、429 以及既有
可重试服务错误仍按原预算处理。认证/余额错误也不会触发压缩模型回退。
模型选择、正常回答的超时和历史压缩策略未调整。

宿主附加的远端业务 MCP 补齐已有的 `builtinMcp` 元信息，使原生适配层按既定规则
将其视为可选服务。此前宿主虽跳过启动前探测，却漏传标记，网关502会使新会话创建失败。
本地必需工具目录的宿主就绪检查和用户自行配置的外部MCP要求不变；网关失败时不伪造工具就绪。

验证方式为固定版本源码调用链审查、Rust 格式/语法解析和 diff 检查。
按仓库规则未执行本机编译或测试，未发布或替换已安装程序；以上不代表实机提速已验证。

## 提前预热

桌面窗口可用、启动维护结束后，分别准备星河和远山。预热不发 prompt、不创建会话，不消耗模型推理请求。只初始化已安装且允许启动的 Agent。

- 星河外部共享后端继续复用既有共享 Host；内部运行器和远山使用独占接管。
- 预热优先选择该 Agent 的已有打开标签，随后采用当前工作区或最近打开的工作区。星河内部运行器绑定恢复 session ID；新会话和恢复会话不能互相接管。
- 配置指纹、工作目录、会话标识、运行时版本和策略代际必须匹配。配置或模型选择变化导致未命中时，正常启动新的运行时。
- 同一 key 的预热和用户启动共用锁；独占实例从预热池移出后只能属于一个会话。活动实例不会被复用给另一个独占会话。
- 星河运行器内部权限指纹仍带实例唯一标识，独立于预热池的配置匹配键。
- 独占匹配包含完整环境（包括并发上限）；用户启动先完成时后到的预热跳过。被接管的独占 Host 用弱引用登记，应用退出也等待其 driver 收尾。
- 保持最多两个空闲 Host 的既有预算；未使用的预热实例启动 120 秒空闲回收。内存紧张或状态未知时跳过预热，活动会话不会被回收。

预热会占用额外的短期常驻内存，收益是首次启动少做进程创建和 initialize。不能把预热后的空闲内存与完全不预热时直接比较，也不能保证所有模型配置都命中同一个预热实例。

实现入口：`src-tauri/src/acp/manager_prewarm.rs`、`connection_prewarm.rs`、`runtime_host_registry/owned.rs`。

## 进程与输出生命周期

普通命令结束不再靠“几百毫秒无输出”判定后代已经结束，也不按 node/python 名称扫描和终止进程。

- 通用 ACP terminal 在 Windows 启动用户代码前加入自己的 Job Object，记录父进程退出后仍存在的后代。
- 一个任务独占 Child，等待 OS 退出事件；输出查询和停止请求不会争抢一个被 wait 长期占用的锁。
- 正常完成等待输出 EOF 和 Job 中活动进程结束，随后发布 exit status 并释放活动计数。后代仍计算、输出或状态未知时保留其所有权。
- 仅明确 kill/release/所属 session 清理时终止该 terminal 的 Job；停止超时保留可查询和重试的终端记录。
- 原生 Agent 连接也拥有自己的 Job。回收触发点是整个协议连接的结束/取消，不是每次模型回复结束。启动器成功退出时继续处理协议输出，直到协议 EOF 或明确取消。
- stderr reader 绑定协议连接生命周期，连接结束后释放自己的 reader、回调和输出缓冲。
- terminal reader 有独立 guard，创建/注册被取消或 monitor 提前退出时回收其 reader。读取失败会记录并通知等待方。没有活动 route/预留的独占 Host 在任务取消时安全关闭，并再次校验代际以保护新接管的任务。
- 创建或绑定 Job 失败会报告错误上下文并降级为既有直接子进程控制；该降级无法保证已脱离父进程的后代回收。显式 breakaway 服务保持既有行为。

星河底层 PTY 对正常退出后后台任务的保留语义未改为全量杀进程。仍在运行的 Node/Python 不能仅因为 UI 上某一步显示完成就认定为泄漏；运行期需要按所属 terminal/连接核验。

实现入口：`terminal_runtime.rs`、`terminal_instance.rs`、`terminal_process.rs`、`terminal_job.rs`，以及 vendored `sacp-tokio/src/connection_child.rs`、`connection_job.rs`。

## 计算和分配

- Node 版本探测按实际可执行文件、长度、修改时间和最终环境摘要复用；30 秒 TTL，最多 8 个条目；并发探测复用同一结果。失败/取消不缓存，手动刷新清空缓存。授权、最低版本判断、配置回读照常执行。
- Node 探测移到环境所有字段投影结束后，避免前后环境不一致导致重复探测；有实际环境变化时仍重新检查。
- 去掉环境准备阶段重复的 gateway 扫描，保留新进程/预热最终入口的严格检查。中央 Skill 缓存指纹扫描、对账、缓存更新全部在阻塞线程执行，互斥 guard 跟随任务，即使请求取消也不会与下一次磁盘写入重叠。
- terminal 增量读取只复制新后缀；状态检查不复制完整输出。UTF-8 offset 落在字符内部时向前对齐，避免切片 panic。
- 预热门禁只查询系统内存，避免枚举所有进程和磁盘。
- 历史缓存文件读取移到阻塞线程；写分页缓存的助手轮次数统计由逐页扫描全部前缀改为一次线性累计，输出格式不变。
- 前端历史 timeline 条目按不可变 turns 引用复用；无状态变化的更新不广播。适配缓存按实际消息 ID 变化清理，避免旧条目在等长替换时残留。

## 首字观测

既有 `[ACP][startup] stage` 增加 `first_content`：`duration_ms` 是 prompt dispatch 到首个非空 ContentDelta 的等待，`since_accepted_ms` 包含本地启动时间。只记录一次时长，不记录 prompt、token 或消息正文。

这可以区分本地启动慢与模型/网关首字慢；本改动不会改变模型、推理参数或用户记忆语义。
