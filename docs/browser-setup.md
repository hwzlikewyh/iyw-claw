# 浏览器连接设置

桌面端入口：设置 → 常规 → 浏览器。内置浏览器开关保持原有含义；
OpenCLI 的安装、修复、扩展引导和连接诊断集中在“外部浏览器”一行。
服务器和远程工作区继续在联网工具页管理服务端运行时，不把服务端路径当成本机路径打开。

## 离线扩展安装

1. 点击“连接浏览器”。应用将内置扩展写入持久目录；如运行时缺失或需要修复，
   使用现有托管安装流程准备 OpenCLI。
2. 选择 Chrome 或 Edge，点击“打开扩展管理”。未找到浏览器时显示错误，
   也可在目标浏览器中手动输入弹窗里的扩展管理地址。
3. 开启开发者模式，点击“加载已解压的扩展程序”，选择弹窗中的目录。
   可直接复制目录或在文件管理器中打开。
4. 应用检查连接；也可以手动点击“检查连接”。自动检查间隔至少 10 秒，
   持续最多约 3 分钟加当前诊断请求的超时时间，关闭弹窗后停止发起新检查。

扩展文件准备完全离线；OpenCLI 运行时缺失时，安装运行时仍需要网络。
应用不会修改用户的浏览器配置或企业策略，开发者模式和加载扩展仍由用户确认。
Chrome/Edge 选择只决定打开哪个扩展管理页，不修改 OpenCLI 默认 profile。
多个 profile 同时连接而未选定默认项时，会显示需要选择配置并保留详细诊断。

扩展目录：`<AgentStoragePaths.root>/browser-extensions/opencli/1.0.24`。
该目录不属于临时缓存，卸载 OpenCLI 运行时时保留，避免浏览器已加载的扩展丢失。

## 版本与诊断

资源在 `src-tauri/resources/opencli/`，运行时固定为 OpenCLI `v1.8.7`，扩展
`1.0.24` 取自 OpenCLI `v1.8.8` 的官方 Release。ZIP 和 Apache-2.0 许可证编入
桌面应用；准备时校验固定 SHA-256，拒绝不安全的 ZIP 路径，并以原子文件替换
方式修复内容。

设置页复用浏览器预检的 doctor 报告解析器。仅当 daemon、extension 和真实
connectivity probe 都正常时显示“已连接”，不再只依赖进程退出码。

## Agent Reach MCP

内置 MCP 网关新增能力 `iyw.internet.agent_reach.status.v1`，内部名称
`get_agent_reach_status`。通过现有能力搜索、读取 schema 和调用流程使用，
参数为空对象，返回 `{ "channels": [...] }`，含渠道状态及当前后端。

该能力复用托管 `agent-reach doctor --json`，沿现有会话鉴权执行，支持取消，
诊断信息脱敏并限制长度。不会新增 Python MCP 常驻进程，不安装渠道或导入凭据。
Agent Reach 上游 MCP 的 `get_status` 同样仅提供诊断；实际搜索和读取继续走
现有平台工具及浏览器能力。

## 验证边界

遵循仓库约定，不新增或运行测试。验证包含定向 ESLint、TypeScript、Rust
桌面/服务器配置的编译检查、资源摘要/manifest 检查和 MCP 注册表一致性检查。
真实浏览器加载扩展、登录状态和跨平台交互仍需安装新版桌面应用后实机验收。
