# 2026-11-05 运行日志失败修复

基于远程 main `26ccedcb`，针对原助理 11 月 4–5 日日志中可以由客户端代码解释的失败修复。

## 验收与边界

1. 受管 uv Python 经 Junction 启动时，安装器能识别其实际可执行文件；路径、同用户、启动时间和停止前复核仍有效。
2. 旧技能在已有读取、启用或发布流程中按需补齐元数据；不增加启动目录遍历、全量校验或后台扫盘，保留正文和市场包完整性规则。
3. SQLite 已知幂等写入在临时锁冲突时有界重试；连接终态缓存保留至持久化成功；会话和输入队列写事务在读取前取得写锁。
4. HTML 上传默认使用正确的 MIME；浏览器能区分下载导航和页面加载，普通页面 DOM 可用时结束等待，拒绝 file URL 的现有边界保留。
5. 账单关联慢写入不因两秒等待超时而取消；只读账户查询对短暂网络错误/502/503/504有界重试。

## 方案

- 安装器复用已编译的 Restart Manager C# helper，通过文件句柄取得进程可执行文件的最终路径。安装目标及脚本继续严格验证，解析后的进程路径仍须落在已验证受管范围。
- 技能复用现有读取、启用或发布入口处理当前技能，不额外遍历用户或星河技能根目录；不引入另一套目录扫描、解析器或远程同步。
- SQLite 复用 retry_sqlite_maintenance；仅重试单条幂等写入或完整回滚的事务，不重放渠道发送或其他外部副作用。事务使用 SeaORM 2.0.3 的 SqliteTransactionMode::Immediate 扩展点，保留只读事务。
- HTML 上传默认采用 text/html; charset=utf-8，显式 MIME 优先，不读取文件内容猜类型。浏览器复用现有页面 IPC 与下载回调记录导航终态，不提高固定超时掩盖下载等待。
- 账单落盘任务拥有待写内容与串行锁；超时只结束调用方等待，后台任务继续写入及同步，失败有日志。
- 账户 POST 的重试严格限于 getMyInfo；登录、验证码、账户修改等写操作不自动重放。消费查询保留现有预算和后续重试。

## 验证方式

依仓库 AGENTS.md 不新增或运行测试套件。实施后检查 Rust 格式、桌面库编译、PowerShell 5.1 语法、C# helper 编译与真实 Junction 只读解析，静态审查取消、并发、失败和资源释放分支。

微软官方 GetFinalPathNameByHandleW 文档说明该接口返回解析符号链接后的最终路径；本机 SeaORM 2.0.3 官方源码确认支持 SQLite IMMEDIATE 事务。浏览器根因由实际会话工具结果确认：上传的 HTML 返回 application/octet-stream，后续两次 open 等待页面加载完成并超时。
