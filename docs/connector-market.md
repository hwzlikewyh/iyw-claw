# 连接器与会话选择

2026-11-09 本地直下改造：安装计划仍由连接器控制面验证发布版本与制品，桌面在下载前用计划中的短时授权请求 `/connector-market/artifact-ticket`，然后直接 GET TOS/CDN 地址，不把用户 token 发给对象存储。文件大小和 SHA-256 与计划再核对，现有缓存/安全解包保持。已发布旧客户端使用的 Gateway 文件流接口保留兼容，待控制面和数据面先部署、真实云端直下验收后再交付新客户端；当前未发布或部署。

连接器市场只从爱原物网关读取。市场页面可以浏览、搜索、配置、卸载；文件连接器下载受管文件，远程连接器保存 HTTP 配置。安装后不会自动开启所有会话。原助理可通过内置 MCP 工具查询、安装、卸载、切换会话或全局状态，并发布包含连接器的便携插件包到插件市场。

## 使用流程

1. 打开能力市场的“连接器”，选择接入方式，填写所需参数后添加。
2. 如果需要 OAuth，在“已安装”中点击“授权 / 重新授权”，打开浏览器完成登录。CLI 连接器点击“CLI 登录 → 开始登录”，按终端提示操作；登录进程退出后另行检查认证及 MCP 连接。
3. 在“已安装”点击“用于当前对话”，或打开输入框的“＋ → 连接器”二级菜单，搜索已检测连接器并切换本次对话的开关。旧的 Agent 全局配置首次被选中时会先请求确认，再迁入应用管理并从全局配置移除；之后只注入所选对话。输入框不再单独显示连接器按钮；菜单底部的“管理连接器”打开市场。发送首条消息之前也可以选择。
4. 选择按对话保存，切换或重新打开后仍然保留。新独立对话默认关闭可选连接器。
5. 正在运行的会话修改选择后，在菜单点击“重连并应用”；生成中禁止重连。

发现页每页展示 20 条，使用“上一页 / 下一页”浏览。搜索由市场服务执行，不局限于已加载页面；输入延迟 300ms 查询，切换搜索会回到第一页。每次只读取一页，不再默认拉取 1000 条。

## 安装任务与恢复（2026-11-06）

市场安装现在通过 begin/list/status/cancel 任务入口复用原安装核心。面板显示准备、缓存检查、下载、校验、解包和提交，下载进度使用实际接收字节。关闭面板可让后台继续；失败和中断任务在市场有“查看安装”入口，目录服务暂不可用时也能查看已有任务结果。

取消只在准备阶段生效。提交目录和凭据时会完成当前操作或回退，避免中途丢弃写入。新配置提交前保留原有条目；目标在安装期间被修改、或账号/企业空间改变时会拒绝覆盖。失败的回退或同步无法完成时，错误会说明需要重新核对和恢复。

任务记录保存在现有 app_metadata，最多 32 条，不保存参数值或账号令牌。重启后无法继续的任务标为中断；重试需要重新填写敏感参数，经过摘要和清单检查的缓存文件可以复用。历史任务完成只表示那次操作结束，不等于当前仍已安装或账号仍有效。

OAuth 面板在原生运行时给出授权地址后打开浏览器；失败、过期可重新发起，先取消上一请求。关闭面板取消待处理授权。CLI 使用独立的结构化登录声明和既有交互终端，不改变原生 OAuth 存储范围。

两种运行模式的编译检查、TypeScript 和定向 lint 已通过；本地组件交互核对 28 项通过。没有宣称完成实际服务登录、真实文件下载或系统重启恢复的实机验收，完整阶段记录见 `capability-market-implementation.md`。

内置网关技能始终走原有默认加载流程，不出现在市场卡片、可选列表和数量中。用户仍然需要登录才能使用相应远程业务能力。

“已配置”只表示安装资料已保存。实际可连接性由智能体的 MCP 运行时反馈，不能把下载完成或保存成功当作握手成功。已卸载连接器仍会显示在曾选择它的对话里，可以关闭该选择或重新安装。

## 兼容范围

| 运行时 | 会话连接器 |
| --- | --- |
| 桌面内置星河 | STDIO、Streamable HTTP；原生 OAuth；拒绝旧版 HTTP+SSE |
| 远山、云舟、流光、逐风、青岚 | STDIO；HTTP/SSE 还需 ACP 握手声明支持；当前不注入 OAuth 或独立 cwd |
| 服务端星河和其他原生全局配置读取器 | 当前不支持隔离，界面明确显示原因 |

平台限制和发布者声明会进一步限制选项。OAuth 授权由内置星河执行，复用其凭据存储和协议实现，支持取消和超时；尚未进行真实 OAuth 服务的实机验收。

## 存储与运行边界

- 市场 provider 固定为 `iyw_gateway`；旧公共 registry 不再作为可用来源。
- 默认市场地址为 `https://gateway.iyw.cn/iyw-fusion-mcp-gateway/api/connector-market`。MCP 网关将列表、详情、安装方案与制品下载四个 POST 读接口转发给 apiserver；管理和发布仍由 apiserver 维护同一份目录。协议、文件/API 示例见网关项目 `docs/connector-market.md`。开发环境通过 `IYW_CONNECTOR_MARKET_BASE_URL` 指定 HTTPS 或 loopback HTTP。
- HTTP 404 提示检查 MCP 网关、控制面部署和市场转发；HTTP/业务 code 401、403 提示登录或权限失效。空目录仍是成功的空状态，不伪装成请求成功。分页版本需与网关、apiserver 一同更新。
- 连接器登记复用现有 MCP catalog；用户密钥放入现有安全存储，目录只保存引用，不写入对话消息或市场服务。重新配置和卸载会清理对应旧引用。
- 会话选择保存到当前应用数据库 `app_metadata` 的 `mcp.conversation.v1.<conversation_id>`，带 revision 防止覆盖其他窗口的更新。
- 选择旧的 Agent 全局连接器时，先确认再将其登记为应用管理，并从支持的 Agent 配置中移除全局副本；选择只注入当前会话。全局启停保留为单独操作。运行中会话在选择变更后需要重连。
- `manage_iyw_connectors` MCP 工具复用现有命令执行连接器查询、市场安装、卸载、会话/全局启停，以及插件包发布、更新和删除。敏感参数与 OAuth 必须在界面处理。市场发布使用已有 Skill/Plugin 市场 API，包类型为 plugin；连接器市场自身暂不提供发布接口。
- 制品最多 32 MiB；ZIP 最多 2048 项、解包总量最多 128 MiB，拒绝路径越界和符号链接。单文件保留文件名；ZIP 保留内部相对路径。
- 文件存入应用数据目录 `connectors/artifacts/<sha256>`，摘要校验后使用 staging 原子激活，复用时检查内容清单。损坏目录会阻止复用；不会擅自删除用户可能修改的文件。
- 卸载清除连接器登记及其应用侧参数密钥，保留共享制品缓存和对话选择。原生 OAuth 令牌沿用运行时自身管理方式，卸载不等于第三方账号撤销授权。

后续各轮已执行桌面/server-runtime 的 Rust 编译检查、TypeScript 和定向 ESLint，详见 `capability-market-implementation.md`。这些检查不代替真实登录、两条对话独立选择、恢复、重连、STDIO/HTTP/SSE 调用及 OAuth 成功/取消/超时的实际验收。

## CLI 登录与连接检查

后台的本地 STDIO 接入方式可以选择 `auth_mode=cli`，填写 `cli_auth`：

```json
{
  "login": {"command": "provider", "args": ["login"]},
  "status": {"command": "provider", "args": ["status"]},
  "logout": {"command": "provider", "args": ["logout"]}
}
```

这里的 `provider` 及参数仅表示结构，发布者须按所用 CLI 官方文档填写，不能直接复制为真实命令。命令直接传入程序和 argv，不经过 shell；Windows 脚本需显式声明相应解释器及脚本参数。`status` 必须无需交互，在有效认证时退出0，未认证时退出非0；`logout` 可选，未声明时不显示断开按钮。状态/断开命令最多15秒，交互登录最多五分钟，关闭窗口取消登录进程。

命令可引用非敏感声明参数、制品目录及专用 `${CONNECTOR_AUTH_DIR}`；密钥只通过原有 env/安全存储传入，不得放在 command/args。登录、状态检查、MCP 启动共享 env/cwd，并覆盖 HOME、USERPROFILE、APPDATA 与 XDG 目录到当前账号、企业空间和连接器的专用目录。采用其他配置路径的 CLI 应在 spec.env 中按官方文档绑定 `${CONNECTOR_AUTH_DIR}`；只使用系统钥匙串、忽略这些目录的第三方 CLI 需由发布者确认其隔离机制，不能把应用目录隔离当作第三方凭据隔离的证明。

“检查连接”先验证 CLI status，再由桌面内置运行时创建不保存历史、不开启模型回合的临时会话，等待此连接器明确 connected 并核对工具目录。单独认证成功或缓存工具信息都不算连接通过。不能执行独立 MCP 检查的环境显示“待会话验证”。通过状态只短时显示；配置、账号或企业空间改变后旧结果丢弃，实际启动会话时重新检查 CLI 认证。

登录进行中阻止同时重新配置/卸载。卸载核对并清理当前账号的 CLI 专用目录，清理失败则保留登记并明确报错以便重试；共享制品缓存保留。断开与卸载后需重连已经运行的会话，不代表第三方服务撤销授权。
