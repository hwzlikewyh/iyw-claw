# 双内核浏览器

桌面版默认使用系统 WebView。用户和 Agent 操作同一个标签，程序选择底层内核，
Agent 无须选择浏览器、安装内核或改变调用参数。

## 设置

“设置 → 常规 → 浏览器”包含：

- 显示内置浏览器：保留现有开关；关闭时内置浏览器工具不可用。
- 启用完整浏览器：默认关闭，使用轻量浏览器；打开且完整组件已校验时启用 Chromix。
- 当前使用：显示实际内核及切换待生效状态。
- 完整内核：显示已安装或未安装，提供安装或修复入口和安装进度。
- 登录与网站数据：说明持久 Profile、同内核共享及跨内核缓存边界。

未安装完整组件时，保持轻量模式。下载完成只更新组件状态；以用户当时保存的开关
为准，不覆盖下载期间的新选择。安装及修复仍使用现有 Fusion 受管事务，不直接
从 GitHub 或 npm 安装。新安装默认跳过 Chromix 和 agent-browser；已有组件继续保留。

## Agent 与用户共用

调用链仍为内置 HTTP MCP 网关 → delegation listener → BrowserSessionManager。
连接鉴权、回合租约、固定标签、取消和人工控制权保持在共享管理器中。

| 行为 | 轻量 WebView | 完整 Chromix |
| --- | --- | --- |
| 用户浏览与 Agent 操作 | 同一原生页面 | 同一 CDP 标签 |
| 打开、读取、快照、点击、填写、按键、滚动、等待 | 原生页面及 codeg Agent 脚本 | 现有 agent-browser 控制器 |
| 页面截图与选择元素发送到会话 | 原生截图与坐标选择 | 现有截图流 |
| 独立窗口与收回 | 迁移原视图，不重开 URL | 现有展示迁移 |
| 人工登录与接管 | 在 Agent 原页面进行 | 在 Agent 原标签进行 |
| 下载、打开文件和定位文件 | 复用现有下载列表 | 复用现有下载列表 |
| 页内查找、停止加载、开发者工具 | 原生工具栏 | 保留现有能力 |

Windows 的点击使用 WebView2 CDP 指针输入；macOS/Linux 使用 codeg 的合成交互路线，
输入质量存在平台差异。轻量模式不启动 agent-browser 或 Chromix。
Windows/macOS 使用原生子视图；Linux 使用独立原生窗口，避免 Wayland 子视图限制。
轻量模式的下载取消目前接入 Windows；其他平台返回明确错误。

高级命令按底层能力执行。轻量模式暂不支持完整内核的 network、trace、profiler、
跨 frame 操作、上传、PDF、视口模拟，以及整页/带引用标注的 Agent 截图选项、
带 selector 的局部快照或带 filter 的读取。这些操作返回结构化错误，不报告虚假
成功，也不暗中启动完整内核重放操作。现有完整内核的高级功能保持原有路径。

## 切换和回收

程序保持一套活动运行时。有页面、Agent 回合持有、人工接管或活动下载时，保存
用户选择并显示待生效，当前任务继续使用原内核。标签关闭且持有关系释放后回收
运行时，后续创建使用选中内核。不能因为面板隐藏或 Agent 正在思考就卸载页面。

原生视图在面板不可见、非活动标签或弹出应用对话框时隐藏；隐藏保留页面状态，
不等于已经释放内存。没有持有关系的 Agent 临时标签沿用既有清理流程。

## 登录数据

每种内核有自己的持久 Profile。用户与 Agent 在同一内核内自然共用 Cookie、
LocalStorage、IndexedDB 和缓存。跨内核不直接复用数据库目录。

同一次应用运行中的切换会经内核 Cookie API 转移普通 Cookie，保留 domain、path、
expiry、Secure、HttpOnly、SameSite；Cookie 值只在内存中转，不写入日志或额外文件。
导入前校验数据，写入失败尝试恢复原值。未能表达的分区 Cookie 会跳过并记录数量。
原助理账号登录同步也接入轻量内核。

HTTP 缓存各自维护；跨内核不迁移 LocalStorage、IndexedDB、Service Worker 或表单
状态。设备绑定和分区 Cookie 可能导致重新登录，不能承诺所有网站无缝切换。
应用重新启动后继续使用各自 Profile；不会为读取另一套登录数据偷偷启动完整内核。

## 验证边界

按仓库规则不新增或运行单元、集成及端到端测试。交付检查使用 TypeScript、定向
ESLint、JavaScript/JSON 语法、Rust 格式解析和静态调用链审查。依照 AGENT.md，
本机不编译、打包或启动桌面应用，也不运行测试。真实网站登录、验证码、弹窗、下载和内存增量需要实机验收；不能用
编译成功替代这些验收。

## 本轮验收与进度

1. 核对已有调用链、设置和 codeg 原生实现 → 已完成静态核对。
2. 补齐设置与安装并发、弹窗回滚、下载清理和 Cookie 迁移 → 已接入并完成静态审查。
3. 检查类型、语法、命令注册和文档一致性 → TypeScript、定向 ESLint、JS/JSON 语法、Rust 格式解析与 diff 检查均通过。
4. 指定构建环境中的桌面编译与实机验收 → 尚未执行。

验收标准：默认轻量内核不启动完整进程；开启且组件健康才选择完整内核；两套内核
共用工具和原标签；切换等待活动任务结束；安装完成不覆盖新选择；普通 Cookie
迁移失败有恢复路径；不支持的功能明确失败。

当前 Fusion 仍把 Chromix 和 agent-browser 列为发布环境必需制品；客户端可以从
已返回的计划中跳过默认下载，显式安装时要求两个制品都存在。后端发布绑定改为
可选组件是独立后端工作，当前未修改。不能仅关闭后台的 InstallOnInitialize：
现有解析器会省略未安装的组件，使显式安装拿不到计划。

Windows Cookie 迁移保留原始域名范围；其他平台使用 Wry Cookie API，无法可靠表达的域名或分区语义仍需站点验证。轻量 Agent 截图返回受配额管理的 PNG 文件路径，沿用现有图片读取方式。
