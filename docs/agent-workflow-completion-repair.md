# 通用 Agent 工作流程：第二批修复

2026-10-29。依据最新实际对话中的指南零复用、压缩中断和反复修改，修复现有运行路径，并补齐通用工作流要求。本批未发布，不能视为实际任务已提速。

## 指南送达与复用

工作进程通过 `completed_snapshot.rs` 发送本轮权威展示内容，并等待宿主确认后结束回合。宿主 `ContentRecovered` 只更新展示投影，不替换模型历史。

此前 `ui_guide_delivery.rs` 在这个事件上清除了 pending，导致紧随其后的正常 `end_turn` 无法确认指南送达。本批移除此处失效；真正的 SessionStarted、压缩标记、上下文用量下降、控制输入、断线和异常仍清除复用状态。

失效日志新增原因和原状态标记，仅状态存在时记录；成功确认也记录一次。`scripts/analyze-agent-startup.mjs` 新增 `uiGuideDelivery` 汇总，按版本、转换和原因计数。旧日志没有新事件时返回空数组，不推断已经复用。

## 压缩失败的恢复

模型切换后，运行时可能仍用旧模型整理历史，再将摘要交给当前模型。此前本地摘要没有旧模型失败后的替代路径；远程摘要虽有替代路径，却会继承旧模型已经耗尽的请求预算。

本批变更：

- 本地摘要失败且历史版本未改变时，对符合条件的故障尝试当前已选模型。只在旧、当前模型或访问程序不同的情况下启用，不自行选择第三个模型。
- 不为本地摘要的取消、认证/支付拒绝、显式配额/限流、内容过滤或不可重试参数错误启动模型替代。
- 替代请求使用独立的单次压缩预算；保留原有 600 秒请求保护，不增加任务总时长、轮数或费用限制。最坏情况可能增加一次请求等待和费用；这条路径旨在恢复工作，不承诺任意服务故障均可完成。
- 本地压缩的原始响应先留在请求内，完成且摘要非空后才写入历史。历史写入在请求超时边界之外；空摘要、失败流和超时不会先留下半份摘要。
- 两个模型尝试共用同一压缩项，最终成功才完成该项，避免留下第一项“仍在运行”的假状态。
- 沿用现有历史构造、附件保留、上下文替换和输入失败持久化路径。替代只执行摘要请求，不重放用户业务工具。

| 文件 | 修改职责 |
| --- | --- |
| `harness/codex/patches/codex-core/src/compact.rs` | 响应摘要校验、延后历史写入、接入本地恢复 |
| `harness/codex/patches/codex-core/src/compact_responses_fallback.rs` | 本地压缩尝试、历史版本门禁、当前模型恢复 |
| `harness/codex/patches/codex-core/src/compact_model_fallback.rs` | 复用模型差异/取消/授权门禁，增加本地适用故障判断 |
| `harness/codex/patches/codex-core/src/compact_remote_v2_installation.rs` | 当前模型替代请求不继承旧模型耗尽的预算 |

这些改动服务于星河的本地和远程摘要路径，不改变其它引擎的压缩协议，也不替代网络、账号和外部服务恢复。

## 批处理、有效迭代和最终交付

`src-tauri/resources/agent-prompt.md` 的通用要求补充：

- 支持时在同一响应里提出独立工具调用；脚本一次提取所需字段与失败，复用有效结果。
- 复杂任务明确交付物和验收项，每次修改对应未满足的检查与预期改善；重复失败时核对证据、修正假设、改换方法，保留最好且验证通过的版本。
- 归因环境或依赖前，独立核对观察结果是否真的违背预期。
- 技能偏好服务于用户交付介质与项目约束，不自行增加无关验收要求。
- 验收通过后交付；最终回复自身包含交付和限制，不能用记忆记录说明代替实际结果。恢复和压缩后先核对最新需求、已有文件、剩余项。

运行时已有 MCP 只读并发门禁，普通生成请求也已允许并行工具请求。本批没有把业务写工具、付费生图或通用 invoke 标记为只读。实际并发和模型是否遵循提示，仍需真实任务验证；本批未新增运行时无进展检测器，不能声称长循环已经被强制消除。
