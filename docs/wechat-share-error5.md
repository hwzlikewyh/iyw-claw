# Windows 微信分享后无内容：错误码 5 修复

## 问题与依据

用户在另一台 Windows 的微信“其他应用”中能看到原助理 0.1.326，点击后没有出现
聊天草稿。该机器的分享包状态为 `Ok`，接收器日志连续三次记录文件读写错误
`os error 5`（拒绝访问）。用户提供的主程序日志中没有成功接收或准备分享批次的记录。

`BatchWriter::commit` 同步 `manifest.json` 后，仍持有文件句柄就调用
`fs::rename(Staging/<id>, Ready/<id>)`。Windows 拒绝移动包含打开文件的目录。
旧接收器随后清理未提交的暂存目录，主应用因此始终收不到 Ready 批次。

开发机使用与产品相同的 Rust 文件打开、同步和移动操作复现错误码 5；关闭句柄后
移动成功。用户在故障电脑运行等价的 PowerShell/.NET 操作，结果也为：

```text
A：文件未关闭，Windows 错误码 = 5
B：关闭文件后，移动成功
临时文件已清理
```

## 改动与验收

1. 在清单同步后显式释放句柄，再执行原子移动。没有放宽目录权限或跳过持久化。
2. 接收器日志补充创建批次、复制文件、提交批次阶段及时间／进程编号；不记录聊天正文或文件名。
3. 按用户最新要求，移除消息渠道页面中的整个“聊天记录导入”设置区块。
4. 为已安装 0.1.326 的 Windows x64 提供签名接收器热修复包；安装时核对版本、签名和摘要，保留旧 EXE 并核验新接收器身份，失败恢复旧文件。

## 验证

- 修复前后文件移动行为已在开发机验证，故障电脑也确认了等价复现。
- 修复后的实际 `iyw-share-core` 已执行两种独立导入：模拟系统复制后的只读文件、手动文件复制。
  两者均完成批次提交、正文解析、附件引用和导入回执，两个批次相互独立、没有 Staging 遗留。
- Windows 接收器 release 编译通过；类型检查与改动页面 ESLint 通过。
- 前端生产构建与静态导出通过（40 个页面）；消息渠道页面已不再渲染该设置区块。
- 已使用现有正式证书签名接收器和 MSIX，验证最终 EXE 清单身份、包版本、签名、时间戳、
  PRI 与图标一致性；接收器热修复安装流程已在开发机执行，新 EXE 的包身份检查成功。
  热修复脚本也通过 Windows PowerShell 5 实际执行及重复安装检查。
- 没有新增测试文件或运行仓库测试套件，一次性复现产生的临时数据已清理。
- 用户已在故障电脑安装签名接收器补丁并重新从微信分享，截图确认新会话输入框收到
  原始 ZIP、聊天记录 Markdown 和附件索引。Windows 文件接收与提交这一段已获实机证据。
  随后用户反馈该正式会话不能发送、且希望内容位于首页；后续修复见
  [首页草稿与发送修复](wechat-share-draft-home.md)。

接收器热修复只更新分享 EXE；设置区块的移除需要包含本次代码的新版主程序。
