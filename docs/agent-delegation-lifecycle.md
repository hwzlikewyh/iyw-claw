# 子代理派发与成果汇合

iyw-claw 提供两条独立的协作路径，均允许父代理在派发后继续执行其他工作。

| 路径 | 启动与结果 | 恢复方式 |
| --- | --- | --- |
| 内置 HTTP MCP | `delegate_to_agent` 完成建连及任务提交后返回 `task_id`；通过 `get_delegation_status` 按需批量收集 | 单次会话；检查已有改动后最多创建一次修正任务 |
| 星河原生协作 | `spawn_agent` 提交任务并返回代理标识；进度与最终结果沿原生消息队列返回 | 对已有代理使用 `followup_task`；`send_message` 不启动空闲代理的新回合 |

## 非阻塞协作

- 每个任务正文包含目标、绝对路径、独占修改范围、约束、验收条件与交付格式。
- 派发后父代理立即继续独立工作；启动回执仅作为异步进度，不作为放行条件。
- 在自然检查点或确实依赖子任务成果时检查状态；没有独立工作可做时才等待。
- 批量收集时移除已结束的任务 ID，防止每次等待都被同一个已完成任务立即唤醒。
- 等待超时不取消任务，不代表限流；无新文件也不代表审查任务没有成果。
- 子代理按仓库约定做定向验证，父代理汇合后做必要的最终验证；不重复运行完整构建。

## 任务正文

MCP 委派通过既有 `ConnectionManager.send_prompt_linked` 提交首条任务，保留
原始正文，并附任务 ID 和直接执行、明确交付的要求，不引入第二套队列。
空白或缺少正文在 listener 返回 `invalid_task`，不会启动子会话。
任务进入命令队列时只记录关联 ID 与正文长度，不记录正文。

星河通过现有 MultiAgentV2 消息生命周期传递任务。明文与密文的选择必须与
工具的实际命名空间一致，支持应用配置的 `agents`、上游 `collaboration`
及平铺工具。仅 `encrypted_function_args: []` 表示明确的明文消息；非空及缺省
标记沿用上游加密约定，不猜测、解密或改写消息正文。

`fork_turns` 只决定继承哪些历史：`none`、`all` 和正整数均不替代 `message`。
首次派发、后续任务与进度消息共用同一条消息类型识别路径。

## 完成与恢复

- `completed` 表示回合结束，父代理仍需验收；只返回“收到”不等于任务完成。
- 审查交付结论和文件依据，不要求新建文件；编码交付实际修改、验证和未完成事项。
- MCP 子回合返回空白结果时，broker 统一转成现有 `child_empty` 失败，包括结果早于任务登记到达的分支。
- 明确缺少任务或仅确认即结束时，先检查已有改动和命令，再完整补发一次；不得不断创建重复任务。
- 接管活跃任务前先取消或中断，确认回合停止并检查遗留进程。取消状态或中断回执不保证后台命令已退出。
- 不自动重跑可能写文件的任务；无法确认停止时不得启动第二个写入者。
