# Fusion 流量与包体复核（2026-11-18）

## 范围与验收

基于 `origin/master` 的 `239c31155` 在独立工作区继续修复。目标是降低重复传输、
重试叠加和无变化刷新，同时保证进行中的账单、授权及用户可见状态及时更新。
不调用真实收费模型、不修改生产配置、不清理用户会话或环境数据。

1. 沿模型重试、压缩、图片上传、生图查询和插件轮询追到实际发送端。
2. 保留状态更新、取消、权限校验和错误恢复的既有入口。
3. 包体调整兼容现有安装器的资源校验，应用仍用完整内嵌静态资源。
4. 静态调用链审查、定向 lint、Rust 编译和前端静态导出通过。

## 数据新鲜度与请求节流

| 数据 | 策略 | 更新边界 |
| --- | --- | --- |
| 待出账请求 | 最短 1 秒查询间隔 | 沿原用量事件及结算重试更新 |
| 已出账、未结算请求 | 最短 5 秒查询间隔 | 优先于历史终态复核 |
| 已落定账单 | 60 秒复核间隔 | 替代前一轮的 10 分钟方案；网络正常且页面刷新时分钟级更新 |
| 失败账单查询 | 3 秒冷却 | 不把失败长期缓存为已结算 |
| 记忆检索模型策略 | 成功缓存 60 秒，失败或不完整结果缓存 30 秒 | 账号隔离；下次实际检索时刷新 |
| 能力授权策略 | 原 60 秒轮询及 ETag | 不拉长权限撤销检查间隔 |
| 插件登录状态 | 原 2 秒串行轮询，最多 5 分钟 | 仅用户开始登录后运行；成功、错误、过期及卸载停止 |
| 插件面板 | 可见时原 5 秒同步及工具事件触发 | 隐藏时不安排新同步；重新可见、聚焦、重连时补读 |

这些是客户端刷新策略，不是网络故障时的实时保证。没有服务端变更推送和流量计量数据，
不能声称已验证生产流量下降比例，或把任何一条路径认定为实际带宽账单的唯一主因。
以历史账单原每 5 秒复核为例，改为 60 秒后同一终态记录的复核频率约降低 12 倍；
新请求和待结算请求不受此降频影响。

## 模型主流量

依据：`harness/codex/patches/codex-core/src/client.rs`、`responses_retry.rs`、
`compact.rs`、`compact_remote_v2.rs`、`session/async_compaction.rs`。
请求策略还核对了当前锁定的官方源码 `d32063f` 中
`model-provider-info/src/lib.rs` 和 `codex-client/src/retry.rs`。

- 官方 HTTP 重试会重新构造并提交请求体；`request_max_retries=10` 允许首发之外再试
  10 次，包含连接、网络和超时故障。流重试在外层另有预算，不能只看单个配置值。
- 内嵌星河已有 Fusion HTTP 5xx 的底层重试禁用，但仍保留传输错误重试。
  现在 managed provider 的底层 HTTP 重试设为 0，交由既有外层有界恢复处理，
  避免两层相乘。外部 Codex 的托管配置从 10 改为 3，未改第三方 SDK 内部实现。
- 原外层普通错误和 504 分开计数。例如先重试 3 次普通断流，再遇到 504，仍可再试
  3 次。现在 managed provider 共用一个总计数：sampling 最多额外 3 次，V2 压缩
  沿已有更低上限最多额外 2 次；普通压缩也统一计数。
- managed provider 不进入无限连接重试，也不在预算耗尽后通过切换传输重置计数。
  其他 provider 保持原策略。输出上限、认证和参数等终态错误仍不当作连接故障重放。
- 实验性后台压缩原来只防同一历史版本重复启动。历史变化时可能替换结果接收端，
  旧请求却仍继续执行。现在同一会话有未完成任务时不再启动新后台压缩。
  该特性默认关闭，不能将此风险直接归因于所有用户的流量。
- 普通自动压缩已有 180 秒请求预算；可恢复失败且未达硬上下文窗口时，按新增
  100,000 tokens 延后再试。模型切换、达到硬窗口及成功压缩有相应状态处理。
  输出额度续接是每用户轮次最多 3 次的独立产品行为，不等同于网络重试，本次保留。

前一轮把 Grok 配置中的 `max_retries=10` 写成 Kimi 不准确，实际在 `patch_grok_toml`。
Claude/CodeBuddy、Grok 和 Hermes 的 10 次配置仍需按各自 SDK 的执行语义另行调整，
不能由 Codex 的实现推断它们的总请求数。

## 图片与生图

| 路径 | 实际行为 | Fusion 压力判断 |
| --- | --- | --- |
| `commands/chat_image_upload.rs` | 申请签名 URL，PUT 对象存储，再检查图片；无自动重传循环 | 业务接口 `/ai-application/api/microModel`，不是 Fusion 模型接口 |
| `managed_image_upload.rs` → `acp/model_gateway/assets.rs` | 本地网关按账号与摘要缓存，互斥合并同图；云端 init 查重，缺失才上传，complete 确认 | 文件直传对象存储；Fusion 主要接收元数据，init/complete 失败最多补一次 |
| `iyw_image/input/asset.rs`、`context.rs` | 同一次调用合并同来源准备和同内容上传；已有 HTTPS 引用直接使用 | 避免批量重复上传，缓存不跨账号共享 |
| `iyw_image/fusion.rs` | 直接提交 `images/generations` 或 `images/edits`，编辑传图片 URL | 没有针对 Fusion 生成接口的 2 秒状态轮询 |
| `iyw_image/poll.rs` 及 native/commerce/fission/studio | 业务任务状态查询，受等待期限、取消和终态约束 | 走业务图片接口；只读查询临时失败最多补 2 次，不重提生成 |
| `iyw_image/recovery/retry.rs` | 仅明确的结果下载/转存失败 502 重提生成 | 两类错误可额外生成 3 次，有新增费用；普通超时、未知结果不重提 |

现有生图批次预算最多 128 次候选执行；若每次均命中上述特殊重提，理论最多 512 次
生成调用。这是显式记录的恢复策略，不能当成普通状态轮询。优先应在服务端对同一
上游结果恢复下载/转存，以免重新生成。客户端不能凭错误码恢复一个未返回的结果 URL。
本轮保留该既有恢复行为，并明确记录风险，未发起付费生图验证。

Fusion 不支持 URL 直传的上游仍可能在服务端还原图片内容；客户端上传去重并不代表
服务端到模型供应商的图片字节已消除。需要 Fusion 的实际进出字节与上游重试统计定量归因。

## 插件轮询

5 秒面板同步完整链路：`use-plugin-panel-updates.ts` → `plugin_app_sync.rs` →
账号作用域/本地注册表对账 → 两次授权校验 → SQLite 最新相关结果。未调用插件工具、
远程资源读取或 Fusion。它有本地 DB、文件和序列化成本，隐藏时停止新同步可减少浪费。

2 秒账号轮询完整链路：`use-plugin-account.ts` → `plugin_preparation/account.rs` →
`router_prepare.rs` → `supervisor_auth.rs` → `authentication.rs` → 插件 MCP `tools/call`。
宿主通过本地 stdio 调插件，插件状态工具是否继续访问 Fusion 取决于该插件实现。
因此不能把这条链路定性为“完全本地”。其并发门禁、30 秒状态超时和 5 分钟总期限保留。

## 其余修正

- 账单缓存到 10,000 条后不再整表清空，只淘汰当前批次所需条目，保留其余冷却状态。
- 技能哈希缓存限定为清单扫描；接管技能前的内容冲突校验始终重新读取文件。
  缓存有效期上限 60 秒，并在写入缓存前复核已读取文件的大小和修改时间。
  保留时间戳且同长度的原地修改仍可能使清单短暂滞后，不能把此缓存当安全校验。
- 环境入口校验落盘的写入及清空在同一锁内完成，避免并发共用临时文件或旧写入覆盖清空。
- 桌宠相关代码及入口已移除；用户原有宠物数据未删除。

## 包体与兼容性

`tauri.conf.json` 保留 `frontendDist=../out`，完整前端仍嵌入应用。
外部 resources 映射改为只复制 `out/index.html`。旧安装器、Windows 载荷脚本和
Linux 重打包脚本仍能找到 `resources/bundle/index.html`；应用本身通过 Tauri
asset resolver 提供页面，不从该兼容目录加载脚本。

此前静态导出有 1,128 个文件、102,170,753 字节，入口 HTML 为 389,495 字节。
同份资源相比，外部副本减少 1,127 个文件、101,781,258 字节，约 97.1 MiB。
这是展开体积和文件数量的确定减少量，不能等同于压缩后的安装包大小减少量。
没有完整签名包和真实安装回归，尚不能报告最终 EXE/ZIP/NSIS 体积或安装速度。
