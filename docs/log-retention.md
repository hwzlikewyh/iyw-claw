# 诊断日志保留

应用启动后在后台执行清理，运行期间每 24 小时再执行一次。应用日志、Codex ACP 日志、
渠道消息日志和托管 Agent 的白名单日志保留最近 7 天。Agent 路径沿用当前存储配置，
包括 profile override；清理不依赖某个 Agent 能否启动。

Codex 的 `logs_*.sqlite` 按 `logs.ts` 删除过期记录，每批最多 200 行，每轮最多 2000 行。
数据库锁最多等待 100ms；批次之间休息 25ms，不连续抢占资源。
已有 incremental auto-vacuum 的数据库分批回收空闲页，然后执行 PASSIVE checkpoint。
单库每轮维护预算约 1 秒，最多回收 1024 页（4KiB 页时为 4MiB）；预算在批次边界检查，
已提交的单条 SQLite 语句仍需结束。未完成的维护留到下一轮，不循环重试。
尚未启用 incremental auto-vacuum 的旧库只删除过期记录，空闲页由 SQLite 后续复用。

数据库占用、扫描或 SQL 错误会记录到应用日志。清理不会删除 DB/WAL/SHM 文件，
不会执行完整 VACUUM，也不会更改数据库迁移记录。退出时的 Agent 文件清理同样排除
SQLite 数据库，避免因日志总量超过阈值而重置整库。

会话正文、目标、队列、记忆、认证信息、插件及运行时文件不在本策略范围内。
手动生成的故障恢复备份也不自动过期，应在确认恢复结果后按需处置。
