# 资源区会话筛选器布局优化设计

## 问题

资源区工具栏当前将搜索框设置为整行宽度，会话筛选器被挤到下一行；会话筛选器使用原生 `select`，打开后会把全部会话一次性展开，遮挡资源内容并降低查找效率。

## 目标与验收标准

- 搜索、会话筛选、视图切换和刷新控件在宽屏下保持紧凑的同一工具栏布局，窄屏下可自然换行。
- 会话筛选使用项目已有的弹出式命令选择器，面板有搜索输入和最大高度，长列表只在面板内滚动。
- “全部会话”仍是默认选项；选择会话后保留现有筛选、分页重置和资源查询行为。
- 没有匹配会话时显示空状态；控件具备可访问名称、当前选择状态和键盘选择能力。
- 不修改后端接口、资源查询数据结构和其他页面的筛选逻辑。

## 设计

`ResourceToolbar` 继续作为资源区筛选和视图操作的单一入口。`ResourceSearch` 在工具栏中使用可伸缩宽度；`ResourceSessionFilter` 从原生 `select` 改为 `Popover + Command`，触发按钮显示当前会话名称，弹出面板内显示“全部会话”和会话选项。命令组件负责文本过滤、高亮和键盘交互，列表设置固定最大高度并允许滚动。

会话选项继续由页面模型提供，筛选值仍使用现有的字符串会话 ID。选择选项时调用原有 `onSessionChange`，由页面层将页码重置为 1；不引入额外状态或 API 请求。当前会话标题为空时复用现有的“未命名”翻译。

## 验证

- 对资源工具栏执行 TypeScript/ESLint 定向检查。
- 静态检查选择器的受控状态、筛选回调、空结果和键盘可达性。
- 检查 diff，确认只修改资源筛选器相关文件和本设计文档。
