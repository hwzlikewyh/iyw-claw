# 模型级思考等级偏好设计

## 背景

模型目录已经为每个模型提供 `default_effort`，但前端目前只按 agent 保存一个思考等级。切换模型时，这个全局值会继续覆盖新模型的后台默认值，用户也无法让不同模型保留各自的思考等级。

## 目标

- 用户手动设置的思考等级按 `agentType + modelId` 保存。
- 模型切换时优先使用该模型的用户偏好。
- 没有该模型的用户偏好时，使用模型目录的 `default_effort`，再回退到该模型第一个可用等级。
- 当前会话和新会话使用同一套解析规则。
- 既有非模型配置偏好和会话模型持久化行为保持不变。

## 方案

扩展现有浏览器本地 selector preference 存储，增加模型配置映射；不新增后端接口、数据库字段或 ACP contract。模型目录的 `modelBehavior` 已包含思考等级选项和后台默认值，前端在构建固定配置快照及模型选择器预览时使用该映射解析当前值。

模型行为配置的解析顺序为：

1. 当前 `agentType` 和 `modelId` 下保存的用户思考等级（且仍在模型可用选项中）。
2. 模型目录的 `default_effort`（且仍在模型可用选项中）。
3. 模型提供的第一个思考等级选项。

模型切换后把解析出的思考等级写入 draft 配置，现有配置同步计划会先确认模型，再应用思考等级。用户从思考等级控件或模型行为预览面板主动选择时，保存到当前模型的映射；未选模型时不写入模型偏好。

旧版按 agent 保存的思考等级不再作为模型默认值使用，避免把上一个模型的等级错误带到没有用户偏好的新模型；其他配置项仍按原有 agent 级存储。

## 数据流

1. 读取本地偏好和后台模型目录。
2. 根据当前模型解析固定配置快照的思考等级。
3. 用户切换模型时更新 draft 模型与对应思考等级。
4. ACP 同步层按现有模型优先顺序应用模型和思考等级。
5. ACP 确认成功后保持当前 draft 和已保存模型记录；思考等级用户选择即时写入本地偏好。

## 边界与错误处理

- 保存的等级不在当前模型选项中时视为无效，继续使用后台默认或首个选项。
- 模型没有思考等级选项时不创建或保留该模型的无效配置。
- localStorage 不可用时沿用当前无持久化行为，后台默认仍可用。
- 不改变后端模型目录或 ACP 返回的数据结构。
