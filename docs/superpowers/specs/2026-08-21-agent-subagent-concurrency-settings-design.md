# Agent 子代理并发设置设计

日期：2026-08-21

## 目标

在设置中提供独立于“多智能体协同”的单会话子 Agent 并发限制。首批接通
Codex、Claude Code 和 OpenCode，同时让所有当前及未来 Agent 至少受到
`iyw-claw` 宿主层限制。

## 验收标准

1. “设置 → Agents”顶部存在独立的“子 Agent 并发”区域，不复用委派设置。
2. 用户可设置 `1–40`，默认值为 `40`，保存后后端返回并展示实际持久化值。
3. 所有经 `iyw-claw` 发起的子 Agent 委派按根会话共享同一个并发上限。
4. Codex 和 Claude Code 同步各自原生限制；OpenCode 如实标记为宿主限制。
5. 新增 Agent 只需声明并发适配策略，不修改设置 UI 或持久化结构。

## 范围

本次包含独立设置 UI、持久化、桌面与服务端命令、宿主并发门禁，以及首批三个
Agent 的原生投射。现有运行进程不热更新；保存后新启动、恢复或重启的 Agent
连接及新建的根会话宿主许可池读取新值。

本次不修改委派深度、委派开关和完成结果缓存；不改写用户的全局 Codex、Claude
Code 或 OpenCode 配置文件；不承诺限制从 `iyw-claw` 外部启动的 Agent 进程。

## 设置交互

设置位于“设置 → Agents”页面顶部，Agent 列表之前。使用一个数字输入：

- 名称：单会话最大并行子 Agent 数
- 范围：`1–40`
- 默认值：`40`
- 保存：显式保存按钮，复用现有设置反馈样式
- 生效提示：保存成功后提示新启动、恢复或重启的 Agent 连接生效；现有运行进程
  不热更新

区域内按当前注册的 Agent 显示精简状态：

- `原生 + 宿主`：Agent 自身限制与宿主门禁均生效
- `宿主`：仅能由 `iyw-claw` 限制

状态来自后端注册信息，UI 不维护 Agent 名单或策略映射。

## 数据模型与接口

新增独立模型 `AgentConcurrencySettings`：

```text
max_concurrent_subagents: u32
agents: [{ agent_type, enforcement }]
```

`max_concurrent_subagents` 持久化到现有 `app_metadata`，键名为
`agent_runtime.max_concurrent_subagents`。缺失或损坏时回退到 `40`。后端始终将
输入约束到 `1–40`，并返回实际值。

新增独立的 get/set 命令及 HTTP handler，遵循项目现有 Tauri/HTTP 双入口、共享
core 函数模式。该模型和接口不并入 `DelegationSettings`。

## Agent 适配

Agent 注册层声明并发执行策略，初始策略如下：

| Agent | 宿主限制 | 原生投射 |
| --- | --- | --- |
| Codex | 是 | 将现有 Codex 多 Agent 配置中的硬编码 `7` 替换为设置值 |
| Claude Code | 是 | 启动时注入 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` |
| OpenCode | 是 | 无；当前公开配置没有原生并发字段 |
| 其他 Agent | 是 | 默认无；后续按注册信息增加适配 |

原生投射只使用 `iyw-claw` 管理的分层配置或子进程环境，不修改用户配置文件。
未声明原生适配的 Agent 仍受宿主门禁，界面不得显示“原生生效”。

## 宿主并发门禁

委派 broker 在创建子连接前获取许可。许可池按根会话隔离，嵌套委派沿父子关系
归属同一根会话；许可从开始创建子连接起持有，到完成、失败或取消后的清理结束时
释放。

新会话从持久化设置创建固定容量许可池。保存设置不调整现有许可池，避免缩容时
中断运行中的子 Agent。并发已满时请求等待许可，同时保持父会话取消可中断等待，
不得先创建超限进程。

该门禁覆盖所有通过内置委派 broker 启动的 Agent，因此未来 Agent 默认即有宿主
限制。Agent 自身在 broker 之外启动的原生子任务，只能在具备原生适配时同步限制。

## 错误处理与可观测性

- 持久化值不可解析时使用默认值并记录不含敏感数据的 warning。
- 获取许可、取消等待、释放许可记录结构化 debug 日志；不在轮询中重复输出。
- 原生投射失败沿现有 Agent 启动失败路径返回，日志包含 Agent 类型和配置阶段。
- UI 保存失败保留用户输入，并展示后端错误；成功后使用后端返回值覆盖输入。
