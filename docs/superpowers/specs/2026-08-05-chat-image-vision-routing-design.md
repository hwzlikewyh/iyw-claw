# 聊天图片视觉路由设计

## 目标

让桌面端通过普通附件入口选择的图片真正作为 ACP 图片内容发送，使 Go
后端可以为不支持视觉的主模型调用已配置的视觉模型进行前置识别，而不是只把
本地路径作为文本交给 Agent。

## 范围

- 支持 PNG、JPEG、WebP 和 GIF 图片附件。
- 单张图片原始大小上限为 10 MiB。
- 普通文件继续使用现有本地路径附件行为。
- 不新增对象存储、图片上传 URL、签名 URL 或图片生命周期管理。
- 不改变现有模型配置和视觉模型映射。

## 桌面端设计

文件选择、拖拽或粘贴得到本地图片后，前端读取文件字节并生成现有 ACP
`image` 内容块：

```json
{
  "type": "image",
  "data": "<base64>",
  "mime_type": "image/png"
}
```

图片在输入框中显示缩略图，并与已有图片查看器“发送到聊天”的附件使用同一
状态和发送路径。非图片仍生成路径徽标。读取失败、格式不支持或超过大小限制时，
发送被阻止并显示具体原因，不静默降级为路径文本。

发送边界再次验证 MIME、大小和 Base64 数据，避免其他入口绕过选择阶段校验。
Agent 声明不支持 ACP 图片时仍发送标准图片块，由后端模型路由决定是否执行视觉
回退；本次不增加基于 ACP Agent 能力的客户端阻断，以免阻止后端的视觉嫁接能力。

## Go 后端设计

补齐 Anthropic Messages 标准图片块的 Canonical 解码分派：

- `type: "image"` + `source.type: "base64"`；
- `type: "image"` + `source.type: "url"`。

复用现有图片解码函数，不引入新协议结构。Chat Completions 的 `image_url` 和
Responses 的 `input_image` 行为保持不变。图片进入 Canonical 请求后，继续沿用
已有 `vision=false + vision_model_id` 的视觉前置分析流程。

## 日志与隐私

一次发送生成一个关联号，并在桌面端附件准备、ACP 请求和 Go 后端视觉回退日志
中沿用。日志记录：关联号、图片数量、MIME、原始字节数、Base64 字符数、协议、
主模型、视觉模型、分支选择、耗时和完整错误原因。

日志不得记录 Base64 正文、data URL、访问令牌或其他凭证。现有统一日志文件约定
保持不变，不新增散落日志文件。

## 错误处理

- 图片读取或编码失败：保留输入内容，显示原始错误摘要，允许用户重试或移除附件。
- 图片超过 10 MiB：发送前阻止，并显示上限和实际大小。
- 后端图片结构无效：返回对应入口协议的参数错误。
- 未配置视觉回退：返回 `vision_fallback_not_configured`，日志包含关联号和模型标识。
- 视觉模型调用失败：不调用主模型，返回协议化错误并保留完整服务端诊断原因。

## 验证

1. 静态检查桌面端从选择图片到 `session/prompt` 的数据链，确认内容块为
   `type: image`，而不是本地路径文本。
2. 验证 PNG/JPEG/WebP/GIF、普通文件、超限图片和读取失败路径。
3. 验证 Go 后端 Messages URL/Base64 图片均可解码，并保持 Chat/Responses 行为。
4. 本地构建桌面端和 Go 后端。
5. 使用小型测试图片调用生产兼容接口，确认非视觉主模型触发视觉前置分析；请求和
   日志中不得出现图片正文。

## 验收标准

- 普通附件入口选择图片后，消息展示图片缩略图且 ACP 请求包含图片块。
- 后端能识别标准 Messages Base64/URL 图片，并按配置调用视觉模型。
- 同一关联号可串联图片准备、发送和视觉回退日志。
- 任何日志均不包含图片 Base64 正文或凭证。
- 普通文件附件和现有图片查看器发送行为不回归。
