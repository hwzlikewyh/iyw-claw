# Agent Binary 空签名下载设计

## 背景

Fusion 版本中心可以发布经过后端来源、大小和 SHA-256 校验的 Agent binary
制品。镜像签名器未配置时，下载票据会返回空 `signature`。当前客户端在票据校验
和归档安装阶段都要求签名非空，导致合法的后端制品在真正下载前被拒绝。

## 目标

- 仅允许 Fusion 版本中心下发的 Agent binary 下载票据使用空签名。
- 空签名制品继续强制校验 HTTPS URL、精确大小和 SHA-256。
- 非空签名继续使用编译进客户端的 Agent release 公钥严格验签。
- 不改变后端接口、托管工具安装、官方 URL fallback 或应用更新行为。

## 客户端行为

### 票据校验

Agent binary 票据必须继续满足：

- URL 使用 HTTPS；debug loopback 例外保持现状。
- URL 不包含用户名或密码。
- `size` 大于零。
- `sha256` 是 64 位十六进制字符串。

`signature` 不再是票据有效性的必要条件。票据刷新时仍比较前后
`signature`；刷新过程中签名发生变化时继续拒绝，避免制品身份漂移。

### 下载与完整性

下载器继续按票据中的精确大小和 SHA-256 校验最终文件。大小或摘要不匹配时，
安装失败且不会进入解压和激活阶段。这是空签名制品的必要完整性门禁。

### 签名验证

- `signature` 为空：跳过 Minisign 验证，记录 warning，继续安装。
- `signature` 非空：要求客户端编译有 Agent release 公钥，并严格验证签名。
- 非空签名格式错误、验签失败或公钥缺失：继续失败，不回退为空签名路径。

进度文案只声明制品完整性已验证，不把空签名制品描述为“签名已验证”。

## 错误与日志

空签名被接受时记录不包含 URL、票据或凭据的 warning，说明当前制品依赖大小和
SHA-256 校验。URL、大小、摘要和非空签名的既有错误分类保持不变。

## 验证

遵循仓库约定，不新增或运行测试。交付前执行：

- Rust 格式检查。
- 静态检查票据校验、下载摘要校验、签名分支和激活前门禁。
- 确认改动只涉及 Agent binary 客户端链路，且非空签名仍然 fail closed。
