# 账号点数分钟刷新设计

## 目标

登录状态下每 60 秒刷新一次全局账号资料，使左侧栏点数以及其他账号资料消费者同步获得最新余额。周期刷新不得因临时网络错误清空现有资料、改变登录状态或触发可见的加载闪烁。

## 方案选择

采用 `IywAccountProvider` 内的全局静默轮询。账号 Context 已经是资料的唯一前端状态源，把刷新放在这里可以一次更新所有消费者，并避免侧栏组件承担数据同步职责。

不采用侧栏局部轮询，因为它会把数据生命周期绑定到具体 UI，其他资料消费者无法同步更新。不新增点数专用后端接口，因为现有 `iyw_account_get_profile` 已返回最新点数，扩大前后端接口范围没有必要。

## 数据流

1. 应用启动仍通过现有公开 `refreshProfile` 完成首次资料加载，并保留当前加载及错误反馈。
2. 状态进入 `authenticated` 后启动 60 秒定时器。
3. 每次定时触发调用现有 `iywAccountGetProfile`，并复用同一进行中请求，避免请求重叠。
4. 请求成功后通过现有 `applyProfile` 更新完整资料，点数消费者随 Context 状态自动重渲染。
5. 请求失败时仅记录失败，保留最近一次成功的资料、点数、错误状态和登录状态。
6. 退出登录、状态不再是 `authenticated` 或 Provider 卸载时清理定时器。

## 边界与错误处理

- 未登录时不启动周期请求。
- 服务端返回未登录资料时沿用 `applyProfile`，状态切换为 `login_required` 并停止后续轮询。
- 周期请求超过一个刷新周期时，下一次触发复用进行中的请求，不并发访问账号接口。
- 手动重试继续使用可见刷新语义；若它与周期刷新重合，则等待同一个请求结果。
- 浏览器或桌面 WebView 在后台可能节流定时器，本设计保证前台正常运行时约每 60 秒刷新，不承诺后台精确调度。
