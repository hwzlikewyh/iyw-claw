# Skill 下架与内置移除自动清理设计

## 背景

原助理当前会在本地保存市场 Skill、内置 Skill 的中央副本，并向各智能体
Skill 目录创建链接或受管复制件。市场 Skill 被服务端下架，或新版应用不再
携带某个内置 Skill 时，历史受管文件可能继续留在用户设备上。

本设计建立自动对账和清理机制。清理必须无感、非阻塞，并且不得误删用户
自行创建的 Skill。

## 目标与验收标准

1. 市场 Skill 被明确下架、软删除或当前用户已失去访问权后，客户端能在后台
   检测并最终删除对应受管安装。
2. 当前版本不再包含某个内置 Skill 时，客户端能根据历史安装记录自动清除其
   中央副本、受管链接、受管复制件和失效策略，不依赖人工维护退休 ID 列表。
3. 用户修改过的受管 Skill 仍按其原始所有权清理；修改内容不改变所有权。
4. 用户自行创建、接管且没有原助理所有权证据的 Skill 不被删除，即使名称或
   ID 与历史内置 Skill 相同。
5. 检查和清理不阻塞应用启动、页面加载、会话恢复、会话创建或 Skill 使用；
   不打断正在运行的会话。
6. 网络失败、未登录、超时或服务端异常不能触发删除。

## 非目标

- 不根据 Skill 名称、目录名或搜索结果猜测所有权。
- 不删除普通用户目录中没有受管标记的 Skill。
- 不在市场列表分页结果之间做差集判断。
- 不为清理结果增加弹窗、确认框或阻断式错误页面。
- 不改变 Skill 安装包格式和既有不可变版本规则。

## 所有权判定

只有存在下列至少一种明确证据时，目录才允许被自动删除：

- 市场 Skill 的 `.iyw-claw-market-skill.json` marker；
- 内置 Skill 历史 manifest 中的安装记录；
- 指向原助理中央 Skill 副本的受管链接；
- 带 `.iyw-claw-managed-copy.json` 且源路径匹配受管中央副本的复制件；
- 插件安装数据库中与市场 Skill ID 对应的受管安装记录。

用户对受管文件的内容修改不移除这些所有权证据。没有上述证据的同名目录视为
用户内容，必须保留。

## 方案

### 市场 Skill 可用性接口

Fusion API 新增用户端批量检查接口。请求携带本地受管安装的 Skill ID 集合，
服务端按当前用户权限返回逐项状态：

- `available`：仍可使用；
- `removed`：已软删除；
- `unlisted`：已下架；
- `inaccessible`：当前用户已无访问权限。

客户端只对成功响应中明确标记为后三种状态的项目安排清理。未出现在响应中的
项目、接口失败和无法解析的项目全部保留，等待后续重试。所有 Snowflake ID
继续以十进制字符串传输和比较。

### 内置 Skill 动态退休检测

当前版本的内置 Skill 元数据集合是现行权威清单，历史 manifest 是原助理曾经
安装过的集合。后台对账使用：

```text
retired = historical_manifest_ids - current_bundled_ids
```

退休判断不再依赖静态 `RETIRED_BUNDLED_EXPERT_IDS`。对退休 ID：

1. 删除指向历史中央副本的受管链接和受管复制件；
2. 删除历史中央副本，包括用户修改过且标记为待确认的副本；
3. 从 manifest 移除记录；
4. 删除与该受管 Skill 关联且已无实体 Skill 的激活策略。

如果同名路径没有历史 manifest、受管链接或受管复制 marker 证明其所有权，
则不进入删除集合。

### 无感后台调度

应用启动和服务端启动的主流程不等待远端检查。现有本地内置 Skill 安装对账
继续在后台维护任务中运行，市场状态检查在登录信息可用后以低优先级启动：

1. 扫描本地受管市场安装；
2. 对 Skill ID 去重并发起一次批量状态检查；
3. 将明确不可用的安装标记为待清理，并立即从后续库存和新会话选择中排除；
4. 没有活动会话或插件租约时执行物理删除；
5. 正在使用时延迟到安全点，并在会话结束或下次启动时重试。

任务使用 single-flight 和退避重试，防止重复请求和磁盘抖动。用户主动执行
Skill reconcile 时可触发同一后台任务，但接口响应不等待远端检查完成。

## 清理边界

普通 Skill 清理包括：

- 中央受管目录；
- 各智能体目录中的受管符号链接、目录联接或复制件；
- 对应的失效激活策略。

插件型 Skill 清理还包括：

- 插件安装数据库记录；
- 插件注册状态；
- 受管插件安装目录；
- 插件附带的 Skill 投影。

若插件仍有运行租约，先禁止其用于新会话，再延迟物理卸载。清理必须复用现有
卸载与回滚路径，不建立第二套文件删除实现。

## 并发与一致性

- 扫描、安装、卸载和退休清理复用现有 Skill mutation lock。
- 同一时刻只运行一个市场下架对账任务。
- 删除前重新读取 marker 或 manifest，避免删除检查后被用户替换的路径。
- 删除部分失败时保留剩余所有权记录，使下一次对账可以继续。
- 只有所有受管实体清理成功后，才移除对应的最终安装记录。
- Inventory revision 在状态排除或物理删除后更新，前端通过既有刷新机制静默
  获取新快照。

## 错误处理与可观测性

- 网络超时、鉴权暂不可用、服务端 5xx 或响应不完整：记录 `warn`，不删除。
- 服务端明确返回不可用状态：记录 Skill ID、slug、状态和计划清理原因。
- 文件或数据库清理失败：记录完整错误上下文并保留待清理状态。
- 成功清理：记录所有权类型、受管路径数量和耗时。
- 日志禁止包含 token、下载票据和完整 Skill 内容。
- 不向用户显示弹窗或阻断式通知。

## 验证方案

### Fusion API

- 批量接口只接受合法字符串 ID，并去重、限制批量大小。
- 公开、本人私有、已下架、软删除和无权访问分别返回正确状态。
- 查询失败时整个请求明确失败，不伪造不可用状态。
- OpenAPI 和用户端集成文档与实现一致。

### iyw-claw

- manifest 中存在而当前内置清单不存在的 Skill 会被识别并清理。
- 修改过的历史受管 Skill 会被清理。
- 无 manifest、marker 或受管复制证据的同名用户 Skill 会保留。
- 市场接口明确返回不可用时会进入清理路径。
- 超时、未登录和服务端错误时不删除。
- 活动会话或插件租约存在时只延迟删除，不中断运行。
- 重复启动和重复 reconcile 保持幂等。

## 实施边界

改动范围限定为：

- `iyw-fusion-api` 的用户端 Skill 可用性查询、DTO、路由、OpenAPI 和聚焦测试；
- `iyw-claw` 的市场客户端、后台维护调度、受管 Skill 清理复用和内置 Skill
  动态退休检测；
- 必要的静默库存刷新和脱敏日志。

不修改数据库 schema，不引入新的前端页面，不改变普通用户 Skill 的编辑和
管理行为。
