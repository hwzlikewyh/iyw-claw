# 微信渠道保存后的扫码授权设计

日期：2026-08-16

## 目标

当用户新增或编辑微信消息渠道并保存后，后端因缺少渠道凭据而连接失败时，界面直接进入现有微信二维码授权流程。用户扫码确认后自动重试该渠道连接，避免用户先保存、再返回渠道列表手动点击连接。

## 范围与约束

- 仅改变 `weixin` 渠道的保存后失败路径。
- 新增或编辑失败时保留已经写入的渠道配置，不删除、不回滚。
- 复用现有 `WeixinQrcodeDialog`、`weixinGetQrcode`、`weixinCheckQrcode` 和 `connectChatChannel`，不新增后端接口。
- `lark`、企微 AI Bot、钉钉等密钥型渠道继续显示“已保存，连接失败”和后端错误。
- 二维码取消、过期或获取失败时，渠道仍保留在列表，用户可稍后从列表重新发起连接。

## 方案

新增和编辑弹窗通过回调向 `ChannelListTab` 报告“已保存但需要微信授权”的渠道 ID。父组件负责关闭表单、刷新列表并设置 `qrcodeChannelId`，从而挂载现有二维码弹窗。二维码弹窗确认授权后调用已有的 `handleWeixinAuthSuccess`：关闭二维码弹窗、重试 `connectChatChannel`、刷新状态并显示连接结果。

保存流程如下：

1. 表单创建或更新渠道，并按现有逻辑重新读取渠道状态。
2. 如果渠道类型为 `weixin` 且运行状态为 `error`，调用扫码授权回调并关闭表单；不再在表单内停留显示失败文本。
3. 其他渠道或非错误状态保持当前行为。
4. 扫码确认后连接成功显示成功提示；重试失败显示脱敏后的连接错误，二维码流程结束。

回调只传递渠道 ID，不传递 token、二维码内容或其他敏感字段。父组件仍以渠道列表和运行状态作为最终显示来源，避免表单局部状态与列表状态不一致。

## 错误处理与生命周期

- 表单保存或刷新列表本身抛错时，沿用现有表单错误展示，不打开二维码。
- 二维码弹窗内部继续负责轮询清理和过期计时；关闭弹窗时停止轮询。
- 扫码成功后的自动连接失败只显示连接错误，不重复自动打开二维码，避免无限重试。
- 回调引用通过现有组件的稳定回调链传递，保证关闭表单后仍能完成连接重试。

## 验证

- 静态检查新增/编辑弹窗的回调类型、依赖数组和父子状态转换。
- 检查非微信渠道的原有“已保存，连接失败”路径未改变。
- 检查 `git diff --check`；按仓库约束不运行桌面构建、Cargo 或前端测试。
- 运行时验收：新增微信渠道保存后出现二维码；扫码确认后自动连接；取消/过期后渠道仍存在且可从列表重新连接。
