# 成果区文件持久化、搜索与分页设计

## 背景

成果区关闭文件预览后，用户会误以为成果文件被移除。现有数据库记录不会因关闭预览而删除，也没有 TTL 或后台过期清理；但成果列表目前一次性加载，数量增大后缺少搜索和分页能力。

## 目标

- 关闭文件预览、成果区对话框或移动端预览时，不改变成果记录及其可见性。
- 成果记录在所属对话中持续可见，刷新或重新打开对话后仍可查询。
- 当前对话和全部成果视图支持按文件名、路径、会话标题搜索，并提供分页。
- 不引入 TTL、自动过期或新的全局成果库；保留现有对话删除级联和源文件状态探测语义。

## API 与后端

`list_task_artifacts` 的请求参数增加可选字段：

- `search: string | null`：去除首尾空白后参与匹配；空字符串等同于无过滤。
- `page: number | null`：从 1 开始，非法或缺失值归一化为 1。
- `page_size: number | null`：缺失值为 50，限制在 1 到 100 之间。

返回值从数组升级为分页对象：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 50
}
```

查询保留现有 `conversation_id`、`folder_id`、`latest_turn_only` 过滤和当前对话树范围。搜索条件对成果 `display_name`、`path`、关联会话标题做不区分大小写匹配；先计算过滤后的总数，再按 `created_at DESC`、`id DESC` 稳定排序取当前页。每页返回前继续执行现有源文件状态探测与状态缓存更新。

关闭预览不会调用删除接口，也不会修改列表过滤条件。对话被删除时沿用外键级联删除；文件本身消失时只标记为 `missing` 或 `inaccessible`。

## 前端交互与状态

- `useTaskArtifacts` 扩展查询参数和分页元数据；搜索词或 scope 变化时页码重置为 1，刷新保留当前条件。
- 成果列表工具栏增加搜索输入框；结果区底部显示总数及上一页/下一页按钮，加载中和边界页禁用对应操作。
- 当前回复底部快捷区继续只显示本轮明确登记的成果，不接入全局分页；“查看全部”对话框使用同一批当前回复数据。
- 单文件预览关闭仅清理选中 ID；成果区对话框关闭后再次打开按同一持久化会话 ID重新查询，记录仍显示。
- 搜索无结果、查询失败、源文件不可用沿用现有空态、重试和状态文案，并补充分页/搜索文案的中英文翻译。

- 定向回归覆盖：请求参数归一化、搜索匹配字段、分页边界、空结果、刷新竞态，以及关闭后重新打开仍能加载同一成果记录。
