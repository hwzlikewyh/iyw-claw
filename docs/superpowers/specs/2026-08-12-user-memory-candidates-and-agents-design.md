# 用户记忆候选合并与智能体策略统一设计

## 背景

用户记忆设置页的“合并候选”弹窗允许当前候选选择另一个未终结候选作为目标。当列表中只有当前候选时，弹窗仍可打开，但下拉列表为空，用户无法完成操作。

同一页面还展示每个智能体的独立记忆开关。产品要求不再让用户分别管理这些开关：所有支持的智能体都默认并持续启用；历史上被关闭的设置也必须恢复为启用。

## 目标

- 只有存在合法的其他候选时，才展示候选的“合并”入口。
- 没有合法目标时不打开空的合并弹窗。
- 移除设置页中的逐智能体记忆开关区域。
- 后端读取、保存和生成能力投影时，将所有受支持智能体统一规范化为启用。
- 保留现有 `perAgent` 数据字段和请求结构，兼容旧版本数据及其他调用方。

## 非目标

- 不改变候选状态机、候选内容、相似度判定或合并 API contract。
- 不删除数据库或本地策略文件中的 `perAgent` 字段。
- 不修改文档开关、总开关、委派继承和 Agent 写入权限的现有语义。

## 设计

### 候选合并入口

前端使用与后端相同的合法目标条件：目标 ID 必须不同于当前候选，且目标状态不能是 `confirmed`、`rejected` 或 `superseded`。设置页按 API 上限分页加载全部候选，并校验各页 revision 一致；数据中途变化时重新加载，避免遗漏后续页的合法目标。`UserMemoryCandidatesPanel` 为每个候选计算是否存在合法目标，并将结果传给 `CandidateRow`。只有存在目标时才渲染“合并”按钮。

`MergeDialog` 保留当前选择和提交逻辑，并对目标列表使用同一过滤条件。弹窗作为防御性边界，在目标列表为空时不渲染选择控件并禁用保存；正常流程不会再从单候选行打开它。

### 智能体策略

Rust 用户记忆策略在待处理事务恢复完成后、生成设置快照、保存部分更新和计算能力投影前，将 `USER_MEMORY_AGENT_TYPES` 中的每个键规范化为 `true`。原始策略读取保留旧值供事务 journal 做 generation 比较，避免升级前中断的事务因新默认值无法恢复。这样旧的 `false` 值会在下一次正常策略加载或保存时恢复，运行时能力也不会继续被旧值关闭。

前端 `UserMemoryPolicyPanel` 删除智能体网格及相关图标、标签和逐项 Switch；`perAgent` 仍作为类型字段保留，以便读取旧响应和提交兼容请求。若后端返回缺失字段，现有默认开启行为继续生效。

### 数据流与兼容性

现有 Tauri/Web transport、用户记忆设置 API 和候选 resolve API 不变。规范化只影响策略值，不改变 revision 之外的请求字段命名。已有本地策略文件无需迁移脚本；加载时内存规范化，保存时原子写回统一后的值。

## 错误处理

- 候选目标为空时，合并按钮不可见，提交按钮始终不可用。
- 候选在弹窗打开后被其他窗口修改时，后端现有 revision 冲突错误继续提示重新加载。
- 策略文件中缺少智能体键时补写为 `true`；非法文件仍沿用现有配置错误处理。

## 验证

- 静态审查候选过滤条件、按钮渲染、resolve 请求和后端策略规范化调用链。
- 对修改后的 TypeScript 文件执行定向类型/语法检查（不启动桌面端）。
- 执行 `git diff --check`，确认没有空白错误或无关文件改动。
- 按仓库 `AGENT.md` 约束，不运行 Cargo、Tauri、桌面构建或测试命令。
