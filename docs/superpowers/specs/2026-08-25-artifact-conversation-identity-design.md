# 成果真实会话归属修复设计

日期：2026-08-25

## 背景

新建会话在前端使用稳定的负数虚拟 ID 保存流式消息和连接状态。会话首次发送后，
后端会创建真实数据库会话，但 `MessageListView` 仍只收到虚拟 ID。成果查询会拒绝
非正数会话 ID，因此“当前会话”和回复底部成果为空；“全部成果”改用文件夹 ID
查询，所以仍能看到已经成功登记的文件。

运行证据确认成果本身已正确登记到真实会话和当前回合。该问题发生在前端成果消费
链路，不是成果生成、数据库写入或回合归属失败。

另一个独立缺口是回复解析器只识别 `present_task_files` 工具名，没有识别通过
`invoke_iyw_capability` 调用稳定 capability ID `iyw.artifacts.present.v1` 的注册记录。

## 目标

- 新建会话落库后，“当前会话”和回复底部成果使用真实数据库会话 ID 查询。
- 已有会话、续接会话和分支会话保持现有行为。
- 直连和网关两种成果注册方式都能严格关联到产生它的回复。
- 明确失败或零接受的注册不展示任何输入路径。
- 页面切换、弹窗重开和应用重启后，结果仍由持久化会话与回合数据确定。
- 不使用时间窗口、文件夹总量或最近成果推断回复归属。

## 非目标

- 不把整个消息运行时从虚拟 ID 重键到真实 ID。
- 不修改数据库 schema、已有成果记录或成果目录结构。
- 不改变“全部成果”的文件夹范围查询。
- 不扩展成果种类、预览能力或 UI 样式。

## 方案

### 成果查询 ID

在 `ConversationTabView` 中保留 `effectiveConversationId` 作为稳定运行时 key，新增一个
只用于持久化成果查询的值：`dbConversationId`。将两者分别传给 `MessageListView`：

- 运行时消息、流式状态、乐观回合继续使用 `effectiveConversationId`。
- 成果弹窗和 `CurrentReplyArtifacts` 使用 `artifactConversationId`。
- 新会话尚未落库时传 `null`，查询返回空；创建成功后值变为真实正数 ID，Hook 的
  filter key 变化并自动重新查询。
- 已有会话的 `artifactConversationId` 从首次渲染就是原会话 ID。

该边界避免触碰 ACP 连接、消息队列和运行时 Store，同时消除成果链路对虚拟 ID 的
误用。

### 网关注册识别

回复成果解析器同时支持两种等价形式：

1. 工具名以 `present_task_files` 结尾；
2. 工具名为 `invoke_iyw_capability`，且输入中的 `capability_id` 严格等于
   `iyw.artifacts.present.v1`。

网关形式只从对应的 `arguments.files` 读取输入引用。成功时优先使用输出中的
`accepted[].path`；输出表示失败或零接受时禁止回退到输入路径。其他 capability ID
不能被识别为成果注册。

### 后端边界

后端继续使用现有的 `conversation_id + turn_generation` 精确查询。前端传入真实会话
ID 后，该查询直接返回当前回合成果。无需新增迁移或修改登记事务。

## 错误与并发

- `artifactConversationId` 为 `null` 时不发起无效后端请求，也不显示旧成果。
- ID 从 `null` 切换为真实值时，已有请求通过 Hook 的 request ID 防陈旧响应覆盖。
- 成果变更事件仍触发现有 debounce 刷新；查询 ID 已变化时使用新的 filter key。
- 注册输出无法解析时，仅在已确认是成果注册调用的前提下回退输入路径。
- 任一注册调用明确失败或返回零接受时，本回复成果保持为空，避免误报交付成功。

## 验收标准

1. 新建会话生成一个成果后，“当前会话”显示该成果，后端日志包含真实
   `conversation_id` 查询。
2. 同一回复底部显示该成果；下一轮没有成果时不重复显示。
3. 已有会话、续接会话和分支会话的成果查询仍使用各自真实会话 ID。
4. 直连和网关注册都能解析成功结果；其他 capability、失败结果和零接受结果不展示。
5. “全部成果”保持文件夹范围，不因本修复改变。
6. 切换标签、关闭再开成果弹窗、刷新或重启后结果一致。

## 验证

- 为成果查询 ID 选择和注册解析增加聚焦 Vitest 回归测试。
- 覆盖新建会话落库前后、已有会话、直连注册、网关注册、错误 capability、失败和
  零接受结果。
- 运行目标测试、目标 ESLint、TypeScript no-emit、Prettier 检查和
  `git diff --check`。
- 静态沿调用链核对弹窗和回复底部均使用真实成果会话 ID。
- 使用本机运行数据库和日志做只读复核；不修改生产数据。
