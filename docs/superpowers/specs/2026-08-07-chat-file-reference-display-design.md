# 聊天文件引用与大图缩略图设计

## 背景

本地文件引用在发送给智能体前会被改写为
`Local file path (use filesystem tools, not MCP resources): <path>`。这段文本适合
智能体读取，但当前后端广播和会话回放复用了改写后的内容，导致用户消息直接显示
完整本地路径。路径不再是 `file://` Markdown 引用后，现有文件徽标解析也无法恢复
文件图标和文件名。

图片目前只有文件选择、粘贴等部分入口会转换为 ACP `image` 内容块。通过 `@`
引用、文件树添加等路径进入的图片仍可能作为普通文件引用显示，无法统一获得缩略图
和大图预览。

## 目标

- 普通文件在用户消息中只显示文件类型图标和文件名。
- 图片从文件选择、拖放、粘贴、`@` 引用和文件树添加等所有入口进入时均显示缩略图。
- 图片缩略图点击后复用现有大图预览与图片编辑能力。
- 用户界面、Tooltip、复制文本和无障碍名称均不显示完整本地路径。
- 智能体仍获得可读取原始文件的完整路径。
- 支持最大 100 MiB 的原始图片，同时避免把 100 MiB 原图直接编码进前端状态、
  IPC、会话日志和智能体请求。
- 历史会话中已经保存的内部路径提示也恢复为文件徽标或图片缩略图。

## 非目标

- 不把 100 MiB 原图直接作为 Base64 ACP 图片块发送。
- 不改变普通非图片远程附件现有的 2 MiB 模型上下文上传限制。
- 不新增对象存储、公共图片 URL 或长期媒体资源服务。
- 不改变智能体的视觉模型选择和视觉回退策略。

## 方案选择

采用“展示语义恢复 + 图片入口统一”的方案：

1. 智能体发送链继续使用现有本地路径提示，保持文件工具可读性。
2. 用户消息适配器识别应用生成的本地路径提示，将其转换为结构化文件展示项。
3. 所有图片入口在发送边界前统一生成派生图片块；原图仍通过本地或托管路径提供给
   智能体。
4. 现有 `ReferenceBadge`、`UserImageAttachments` 和 `ImagePreviewDialog` 继续作为
   唯一展示组件。

不采用单纯 CSS 截断，因为复制、跨客户端广播和历史回放仍会暴露路径；暂不引入
独立消息持久化或 `displayBlocks` 数据库，因为当前目标可在现有会话格式上兼容实现。

## 数据流

### 普通文件

1. 编辑器继续生成带 `file://` URI 的文件引用。
2. 发送端继续将引用改写为智能体可理解的本地路径提示。
3. 用户消息适配器仅对用户角色解析该应用生成的提示，提取路径、文件名和扩展名。
4. 展示模型只向 React 组件暴露文件名、文件类别和内部打开句柄；完整路径不作为
   可见文本或 Tooltip 内容。
5. 点击文件徽标时，内部打开句柄仍使用原始路径调用现有文件打开能力。

旧消息与跨客户端消息经过同一适配器，因此无需迁移会话文件。解析失败时保留原始
文本，避免误删普通用户内容；只识别应用固定前缀和合法的行内代码路径格式。

### 图片

所有支持的图片入口统一产出以下两类数据：

- 原图引用：本地绝对路径，或浏览器/远程模式下托管到会话附件目录的路径。
- 派生图片块：用于聊天缩略图、预览和智能体视觉输入的受控尺寸图片。

对于 `@` 引用和文件树添加的图片，发送前读取原图元数据并生成派生图片块。智能体
请求同时保留原图路径提示和派生 `image` 块；展示适配器隐藏对应路径提示，只显示
缩略图。若历史消息只有路径而没有图片块，展示层按需请求派生缩略图，成功后显示
缩略图，失败则回退为图片文件徽标。

## 图片资源边界

- 原始图片上限：100 MiB，按二进制字节计算。
- 派生图片最长边：2048 px，保持宽高比和方向。
- 派生图片编码后上限：10 MiB。
- 支持格式：PNG、JPEG、WebP 和 GIF；GIF 派生图使用首帧，原图保持不变。
- 缩略图沿用现有 56 x 56 px、`object-cover` 样式。
- 原图不进入 React 长期状态；状态中只保存派生图片数据和必要元数据。
- 日志只记录文件名、MIME、原始字节数、派生字节数、尺寸和处理耗时，不记录完整
  路径、Base64 正文或图片内容。

本地路径图片由 Rust 侧进行限量读取、解码、方向处理和降采样，避免 100 MiB 原图
先转为约 133 MiB Base64 再经过 IPC。浏览器 `File` 图片优先通过 Blob/Canvas 生成
派生图；需要让远程智能体访问原图时，通过独立的 POST 流式暂存入口写入会话附件
目录。该入口只接收受支持的图片 MIME，单文件上限为 100 MiB，并采用分块写入和
失败清理；现有通用模型上下文附件接口及其 2 MiB 上限保持不变。

## 展示与交互

### 普通文件

- Excel、CSV：`FileSpreadsheet`。
- 文档、PDF、文本：`FileText`。
- 代码文件：`FileCode`。
- 压缩包：`Archive`。
- 其他文件：`File`。
- 徽标只显示文件名，超长文件名使用现有截断样式。
- 点击徽标使用现有逻辑打开文件。
- Tooltip 只显示文件名或“打开 <文件名>”，不显示路径。

### 图片

- 用户消息顶部沿用现有 56 x 56 px 缩略图列表。
- 点击缩略图打开现有 `ImagePreviewDialog`，多图继续支持前后导航。
- 预览失败时显示图片文件徽标和明确错误状态，不显示路径。
- 同一图片不同时显示文件徽标和缩略图。

## 复制与可访问性

- 复制用户消息时，普通文件输出文件名，图片输出图片文件名。
- 不复制内部英文提示、反引号或完整路径。
- `aria-label` 使用“文件：<文件名>”或“图片：<文件名>”。
- 图标保持装饰性，避免屏幕阅读器重复朗读。

## 错误处理

- 原图超过 100 MiB：阻止图片处理，提示文件名、实际大小和 100 MiB 上限。
- 解码或降采样失败：保留原图引用并回退为文件徽标，允许智能体使用文件工具读取。
- 派生图片超过 10 MiB：逐级降低质量或尺寸；仍无法满足限制时回退为文件徽标。
- 原图在历史回放时已被移动或删除：显示文件名和不可预览状态，不泄漏旧路径。
- 远程原图托管失败：不丢失正文，显示错误并保留待重试附件。
- 远程暂存入口遇到非图片 MIME、请求中断或写入失败：删除未完成文件并返回结构化
  错误，不把半成品路径交给智能体。

## 改动边界

预计涉及：

- 本地文件提示的解析与展示归一化。
- 用户消息适配器、复制文本归一化和文件徽标图标选择。
- 图片入口统一、派生图片准备命令及前端调用。
- 图片读取、降采样所需的 Rust 图片格式特性。
- 相关中英文提示文案。

不修改数据库 schema，不引入新的持久化服务，不改变视觉模型路由。启用 Rust
`image` 依赖的 JPEG/GIF 解码特性属于根依赖配置调整，实施前按项目规则单独确认。

## 验证

按仓库约定不新增或运行测试文件。交付前执行定向静态检查并沿调用链审查：

- 普通文件在乐观消息、跨客户端广播和历史回放中均只显示图标与文件名。
- Tooltip、复制文本、无障碍名称和错误提示不包含完整路径。
- 文件选择、拖放、粘贴、`@` 引用和文件树添加的图片均显示缩略图并可预览。
- 小图直接生成派生块；接近 100 MiB 的原图不以完整 Base64 经过 IPC。
- 超过 100 MiB、解码失败、派生图超限、文件删除和远程托管失败均正确回退。
- 智能体请求仍包含原图路径提示，并只携带不超过 10 MiB 的派生图片块。
- 对修改文件执行 ESLint、TypeScript 检查和 Rust `cargo check`；不运行测试命令。

## 验收标准

- 截图中的内部英文提示和完整路径不再出现在用户界面。
- 普通文件仅显示正确类型图标和文件名，点击可打开。
- 所有图片入口均显示缩略图，点击可打开大图预览。
- 最大 100 MiB 原图可以被接收和处理，但不会作为完整 Base64 图片块发送。
- 历史消息无需迁移即可获得相同展示结果。
