# 能力市场技能自动更新设计

## 目标

在「常规」设置页增加“自动更新已安装技能”开关，默认开启。开启后，应用后台定期检查能力市场中本地安装的技能，并自动更新普通技能与专家包；插件包不静默更新，仍由用户在能力市场手动更新。

## 范围与排除

- 纳入：通过能力市场安装、且存在本地市场安装标记或插件安装记录的普通技能与专家包。
- 排除：用户手工创建/导入的技能、随应用发布的系统内置技能、能力市场插件包的静默更新。
- 手动更新插件时继续沿用现有能力市场安装流程，可与普通技能/专家包统一执行其依赖更新。

## 设置与数据流

1. 前端「常规」页加载并保存 `autoUpdateInstalledSkills` 偏好，后端通过现有 SQLite 元数据服务持久化，缺省值为 `true`。
2. 桌面 Tauri 命令与服务端 HTTP handler 共用同一 core 读写函数。
3. 开关关闭后立即阻止下一轮后台检查；不强行中断已提交的安装事务。
4. 保存失败时前端回滚开关并显示错误。

## 后台检查与更新

- 进程启动后等待 5 分钟，之后每 30 分钟执行一次；每轮重新读取偏好。
- 从本地安装标记和插件安装记录生成 `id + installedVersion` 清单。
- 调用 Fusion API 批量接口 `POST /skills/updates/check`，单次最多提交 256 项；本地数量超过上限时仅按 ID 分块，不扫描或分页市场目录。
- Fusion API 权威判断可见性、SemVer、包类型和制品状态，返回可更新项及必要的安装版本/状态。
- 客户端过滤 `packageType`：普通 `skill` 和 `expert` 自动更新；`plugin` 只报告待手动更新，不进入后台安装。
- 自动更新沿用原安装目标和现有 `install_core`/依赖解析事务，不降级、不改变启用状态和 Agent 发布范围。
- 自动更新、手动安装、更新、卸载共用现有技能变更互斥锁；锁被占用时本轮跳过，下一轮重试。
- 市场查询失败结束本轮并记录错误；单个技能失败记录技能 ID、旧/新版本、目标 Agent 和错误后继续其他技能。

## Fusion API 合约

新增 `POST /skills/updates/check`，请求示例：

```json
{
  "items": [
    { "id": "333124638026498050", "installedVersion": "1.2.0" }
  ]
}
```

响应至少包含每个请求项的状态；可更新项返回 `id`、`slug`、`installedVersion`、`currentVersion`、`packageType`、制品可用状态及必要的依赖/安装计划引用。不可用或无更新项可省略版本与包类型字段。接口保留已下架、不可访问和无更新状态，客户端不得因查询失败删除本地安装。请求 ID 去重并限制最多 256 项。

## 前端界面

「常规」页新增独立“技能更新”区块，使用现有 `SettingSection`、`SettingRow` 和 `Switch`。中文与英文文案同步维护，说明明确只自动更新能力市场安装的技能；插件包仍需手动更新。

## 错误与可观测性

- 不记录技能包内容、令牌或凭证。
- 记录检查批次、候选数量、跳过的插件数量、成功/失败数量和外部接口错误。
- 安装失败不影响同批其他项；不因暂时网络失败清理本地技能。

## 验证

- 静态检查偏好默认值、读写入口、前端回滚、后台任务启动点和桌面/服务端共用路径。
- 检查批量请求分块上限、结果映射、SemVer 过滤、插件排除、原目标保留、锁竞争和单项失败继续。
- 运行项目要求的前端 lint 与 Rust `cargo check`；不新增测试文件，遵循仓库 AGENTS.md 的测试约定。
