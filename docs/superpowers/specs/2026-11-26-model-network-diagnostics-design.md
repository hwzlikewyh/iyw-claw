# 模型网络异常诊断设计

## 背景

基线为 GitHub `main` 的 `23c5db13477b0bae4bcd1b8076126906e2d3c40f`（2026-11-25）。该版本已有网络延迟/流量检测、应用代理设置和模型网络异常横幅。异常横幅目前只说明模型请求正在重试或本轮回复未完成。网络检测结果没有在模型异常时展示。

应用支持桌面、本地服务端和浏览器连接服务端。桌面端网络探测运行在用户电脑上。浏览器连接服务端时，既要观察浏览器到应用服务端的连接，也要单独读取服务端发起的网络探测结果。

## 目标

1. 模型连接、超时或流中断时，自动检查当前运行环境的网络状态，并避免在重试期间重复探测。
2. 向用户清楚说明其电脑侧可确认的网络和应用代理状态，以及可以采取的排查步骤。
3. 把服务端或模型服务侧的原因概括呈现，不暴露内部端点、凭据或原始错误串。
4. 区分已确认、疑似和无法确认的诊断结果，避免把相关性描述为确定根因。

## 范围

- 所有智能体的模型网络错误、请求超时、服务不可用和流中断进入诊断流程。
- 额度、鉴权、权限、限流、模型未开通等非网络错误不触发网络探测。
- 复用现有延迟探测、健康检查、系统代理设置和异常横幅。
- 诊断细节在现有模型网络提示中展开，保留自动重试状态和当前对话发送流程。
- 不持续后台扫描网络，不新增外部服务依赖，不修改模型认证或请求重试策略。

## 方案

### 检测时机

当模型网络错误首次出现时执行一次轻量检查。相同失败仍处于自动重试期间时复用本轮结果；错误恢复后重置诊断状态。检测需要有界超时，不能阻塞消息发送或停止现有重试。

### 桌面端本机检查

桌面模式的既有网络探测运行在用户电脑上。诊断复用延迟探测结果，并读取“原助理代理”应用开关状态。代理 URL 只用于运行时检查，不进入 UI 或诊断日志。系统代理、进程外部设置的代理和系统级 VPN/TUN 不在应用现有可读接口内，不能从应用开关推断；无法读取时明确标为“无法确认”。

如果延迟探测失败，根据可识别的 DNS、连接拒绝、连接重置、超时或 TLS 错误显示对应中文说明和用户可执行的检查步骤。分类只读取现有错误详情中的白名单关键词，原始详情不进入界面。代理已启用时，明确提示用户检查代理软件运行状态和代理设置。测速成功时只报告该测速目标可访问，不据此保证模型供应商可访问。

系统级 VPN/TUN 状态标记为“无法确认”。代理状态字段明确标注为应用代理，避免把应用设置推断成操作系统代理或 VPN 状态。

### 浏览器与服务端检查

浏览器客户端通过现有健康检查观察浏览器到应用服务端的可达性和往返耗时。应用服务端通过既有延迟探测检查服务端的外网连接。界面将两项结果分别标为“本机到应用服务端”和“应用服务端网络”。服务端侧只给出“服务端或模型服务暂时不可用”一类概括信息，不展示内网地址、上游端点或服务端原始诊断。

远程桌面使用浏览器到远程应用服务端的连接检查。通过远程传输读取到的代理设置属于应用服务端设置，不标成用户电脑的代理状态；用户电脑的系统级代理或 VPN 状态显示为“无法确认”。

### 界面与提示

沿用聊天区已有模型网络横幅，异常期间显示简短状态和“诊断详情”展开项。详情按本机网络、应用代理、应用服务端网络分行展示，状态值使用“正常”“波动”“失败”或“无法确认”。

提示文本明确区分观测结果和推测原因。例如本机测速失败且应用代理开启时，提示先检查代理软件和本机网络；本机测速可用而服务端请求失败时，说明本机到测速目标可访问，问题更可能位于服务端或模型供应商侧。

所有用户可见文本沿用 `next-intl`，至少维护简体中文和英语文案。原始错误只用于白名单分类，不直接回显。

### 隐私与日志

- 不显示或记录代理 URL、用户名、密码、API Key、Authorization、请求正文或完整个人信息。
- 日志只记录探测类型、耗时、状态、白名单错误类别和代理是否启用。
- 错误无法分类时使用“暂时无法确定具体原因”，不猜测唯一根因。

## 验收标准

1. 网络类模型异常会触发一次有界诊断，同一自动重试周期不会重复发起测速。
2. 额度、鉴权、限流和模型不可用等错误不会触发网络诊断。
3. 桌面端能说明本机测速结果及应用代理开关状态，并针对可识别的 DNS、连接拒绝、连接重置、超时和 TLS 失败给出清晰中文步骤。
4. 浏览器部署分别呈现浏览器到服务端和服务端出网探测结果，服务端原因保持概括。
5. 应用代理设置与系统 VPN/TUN 状态分别表达；不可观测时明确显示“无法确认”。
6. 界面、日志和错误提示不暴露代理地址、认证信息、请求正文或原始错误串。

## 验证计划

- 按仓库 `AGENT.md` 与 `AGENTS.md` 执行静态审查，不运行单元、集成或端到端测试，不在本机运行桌面构建或 Rust 编译。
- 对本次改动运行允许的定向 ESLint、格式和 `git diff --check` 检查。
- 逐项审查错误分类、超时与重试去重、Tauri/浏览器/远程桌面数据源、未知状态呈现和敏感信息脱敏。

## 决策记录

- 默认覆盖所有智能体的模型网络异常，符合用户原始表述。
- 使用错误触发的一次性诊断，避免持续探测造成额外流量。
- 系统级 VPN/TUN 只在可确认的平台信号存在时展示确认状态；无法读取时呈现“无法确认”。
- 设计文档先由用户审阅。提交设计文档或代码前遵循仓库授权边界，不改写已有远程历史。
