# 标题栏更新入口设计

## 目标

在工作区主界面标题栏增加两个应用级入口：

- 在“原助理 v{version}”前显示现有应用图标。
- 在搜索按钮旁显示常驻更新按钮；发现可用版本或等待重启时显示小红点，点击后打开独立更新 Dialog。

更新检查、下载安装和重启继续使用现有全局更新状态，不新增后端接口，不改变强制更新、自动检查或服务器更新策略。

## 组件边界

### `FolderTitleBar`

仅负责标题栏布局：

- 使用现有 `AppIcon` 渲染品牌图标。
- 在桌面端和移动端的搜索按钮旁挂载 `TitleBarUpdateControl`。
- 不在标题栏组件内实现更新业务状态，避免继续扩大该文件。

### `TitleBarUpdateControl`

新增独立组件，负责更新按钮、红点和 Dialog：

- 从 `UpdateProvider` 读取权威的 `AppUpdateState`。
- 使用现有 `checkAppUpdate` 发起手动检查。
- 使用 Provider 暴露的 `startUpdate` 和 `restart` 执行安装与重启。
- 使用 `getCurrentAppVersion` 获取当前运行版本；远程工作区仍通过现有 transport 查询对应服务端版本。
- 保留手动检查返回的 `selfUpdateSupported`、`liveProgress` 和 `runtime` 能力信息，用于决定执行在线更新还是查看发布页；这些信息只描述能力，不形成第二套生命周期状态。
- 复用 `SystemSettings` 已有国际化文案，不增加仅支持部分语言的新文案。

不修改 `UpdateContextValue`、后端命令、共享类型或数据库结构。

## 交互与状态

更新按钮使用项目现有 Lucide `ArrowUpCircle`，尺寸与搜索按钮一致，并提供 `title` 和 `aria-label`。

红点规则：

- `available`、`downloading`、`verifying`、`installing`、`ready_to_restart` 时显示。
- `idle`、`checking`、`restarting`、`error` 时不显示。
- 检查或更新执行期间图标显示旋转状态，按钮仍可打开 Dialog，但不会重复触发更新操作。

Dialog 打开规则：

- 当前为 `idle` 或 `error` 时自动执行一次手动检查。
- 已有可用版本、正在更新或等待重启时直接展示当前状态，不重复检查。
- 检查失败时保留 Dialog，并提供重新检查按钮。
- 关闭 Dialog 不取消后台下载或安装，全局 Provider 继续同步状态。

Dialog 展示以下状态：

- 检查中：显示加载状态和当前版本。
- 已是最新：显示当前版本和“当前已经是最新版本”。
- 发现更新：显示当前版本、目标版本、渠道、必要时的强制更新标记及发布说明。
- 下载或安装中：显示阶段、已知时显示下载百分比。
- 等待重启：显示“重启以更新”操作。
- 失败：显示与系统设置一致的错误信息和“检查更新”重试操作。

高级设置继续保留在系统设置中，本 Dialog 不提供自动检查开关、渠道切换、跳过版本、稍后提醒或回滚，避免复制完整设置页。

## 布局

- 桌面端品牌图标使用 14 至 16 像素固定尺寸，与版本文字保持紧凑间距。
- 更新按钮放在搜索按钮相邻位置，保持现有 24 像素桌面按钮和 32 像素移动按钮规格。
- 红点绝对定位于按钮右上角，使用 `destructive` 语义色并增加背景描边，避免在深浅主题下失去边界。
- Dialog 使用现有 `Dialog` 组件，宽度不超过 `max-w-lg`，内容区域允许纵向滚动；发布说明设置最大高度，避免长文本超出视口。
- Dialog 内不嵌套装饰性卡片，仅用分隔线和紧凑的信息行组织版本与进度。

## 错误与并发

- 手动检查错误通过现有 `normalizeAppUpdateError` 归一化，并记录完整错误到控制台；Dialog 显示与系统设置一致的错误消息。
- 以 Provider 的 `isBusy` 和后端状态为并发门禁，不在检查、安装或重启期间重复提交动作。
- Provider 事件是更新状态的唯一权威来源；手动检查结果仅补充当前版本和服务端更新能力，不创建第二套生命周期状态。
- 远程旧版本不支持在线安装时，沿用现有能力判断并提供查看发布页入口，不调用不兼容的更新动作。

## 验收标准

- 桌面标题栏“原助理 v{version}”前显示应用图标。
- 桌面端和移动端搜索按钮旁均显示更新按钮。
- 有可操作更新时显示小红点，无更新时不显示。
- 点击更新按钮始终打开独立 Dialog，不跳转系统设置。
- Dialog 打开后能完成检查、展示更新、启动安装、显示进度和触发重启的现有流程。
- Dialog 关闭后，正在执行的更新不被取消，再次打开能恢复当前状态。
- 不影响状态栏更新入口、系统设置更新区块和强制更新门禁。

## 验证

- 静态检查标题栏、Dialog、Provider 和 updater 调用链，确认状态与动作闭环。
- 静态检查桌面端、移动端、无更新、有更新、更新中、等待重启和错误分支。
- 运行 `git diff --check` 检查补丁格式。
- 遵循仓库规则，不运行构建、单元测试、集成测试或端到端测试。
