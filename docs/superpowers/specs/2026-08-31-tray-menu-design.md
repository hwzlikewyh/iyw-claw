# 托盘菜单优化设计

## 目标

让系统托盘成为 iyw-claw 的轻量工作入口：左键快速唤回工作台，右键提供少量高频操作，并保持窗口关闭、后台运行和退出行为一致。

## 菜单结构

右键菜单使用 Tauri 原生菜单，按以下顺序分组：

1. 不可点击的运行状态
2. 打开工作台
3. 新建会话
4. 最近项目（最多显示 5 个项目）
5. 设置
6. 检查更新
7. 退出原助理

最近项目复用现有文件夹历史数据，只显示未删除的普通项目；没有项目时显示禁用的空状态项。菜单文本随应用语言刷新，项目数据变化时同步刷新菜单。

## 事件与数据流

- Rust 创建和刷新原生菜单，菜单点击统一经过 `tray:` 命名空间。
- `open` 直接恢复主窗口；`quit` 直接请求进程退出。
- 其他动作先恢复主窗口，再通过 `workspace://tray-action` 发送给主窗口。
- 主窗口的 `TrayActionBridge` 复用现有 Tab、工作区、设置和更新 API：
  - `new` 使用当前文件夹创建会话，没有当前文件夹时创建 chat-mode 会话。
  - `recent` 按文件夹 ID 加入工作区，并切换已有会话或创建新会话。
  - `settings` 打开现有设置窗口。
  - `update` 使用现有手动更新检查流程，更新状态仍由 `UpdateProvider` 负责。

## 行为边界

- 左键托盘图标仍只负责显示并聚焦工作台。
- 关闭窗口的“隐藏到托盘 / 退出”记忆逻辑不变。
- 最近项目刷新仅在本地桌面执行，远程桌面不会修改本机托盘。
- 菜单动作失败使用现有 toast 和日志路径反馈，不在 Rust 菜单层复制业务状态。

## 验收标准

- 右键菜单在中文和英文下均包含状态、工作台、新建会话、最近项目、设置、更新和退出分组。
- 最近项目最多 5 项，并能打开对应工作区。
- 托盘动作不会重复创建设置窗口或绕过现有更新状态管理。
- Rust 格式检查、前端定向 lint 和 `git diff --check` 通过；不运行桌面构建或测试命令。
