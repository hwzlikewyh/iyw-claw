# 内置执行工具具体操作展示设计

## 目标

当智能体通过内置 `invoke_iyw_capability` 执行能力时，聊天中的折叠卡片标题应直接说明实际执行的能力，而不是始终显示“调用工具”。用户无需展开卡片即可判断当前或历史调用正在做什么。

## 用户体验

- 已知能力显示现有本地化能力名称，例如 `iyw.automation.tasks.list.v1` 显示“查看计划任务”。
- 直接调用已解析为具体内置能力的工具继续显示该能力名称。
- 卡片展开后的结果展示保持现状。
- 内部路由字段和完整网关参数继续隐藏；本次只调整卡片标题。
- 标题解析不到已知能力时，优先使用参数中的显式工具名、操作名或能力名称。
- 仍无法解析时，从能力 ID 生成可读的回退标题，避免退回通用“调用工具”。
- 无任何能力信息时，保留现有通用工具标题作为最终回退。

## 解析设计

`src/lib/builtin-tool-display.ts` 继续作为内置能力展示信息的唯一解析入口。解析按以下优先级工作：

1. 从输入及 `input`、`arguments`、`params`、`payload` 嵌套对象中读取 `capability_id`。
2. 用已有能力 ID 映射解析本地化工具名；该映射继续覆盖静态内置能力。
3. 对未登记的能力，读取参数里的 `tool_name`、`toolName`、`name` 或 `operation` 等显式身份字段。
4. 如果只有未知能力 ID，将其拆分为可读的末段名称，去除版本后缀并转换为自然语言标题。
5. 没有可用身份信息时返回空结果，由现有通用工具标题逻辑处理。

解析器返回的数据仍包含本地化所需的稳定工具名以及隐藏内部参数的标记。`content-parts-renderer.tsx` 只消费该结果生成标题，不重复实现能力 ID 解析。

## 国际化

已登记能力继续复用 `Folder.chat.contentParts.builtinTool` 下的中英文翻译。动态或未知能力的回退标题使用现有通用“工具”文案和安全的可读名称，不直接依赖服务端返回的用户可见句子，也不把原始 JSON 作为标题。

## 错误和边界

- 输入不是合法 JSON、字段类型错误或嵌套层级过深时，解析器应安全返回下一级回退结果。
- 空字符串、过长或包含控制字符的身份值不能成为标题。
- 未知能力 ID 不应阻塞结果展示；解析失败只影响标题，不影响工具结果和错误状态。
- 既有直接工具、委托工具、文件工具和命令工具的标题行为保持不变。

## 验证

通过纯函数级回归验证以下场景：

- 已知能力 ID 映射到本地化能力名称。
- 嵌套 `arguments.capability_id` 能正确解析。
- 未知能力 ID 能生成稳定、可读的回退标题。
- 显式工具名优先于不明确的通用网关名称。
- 缺少能力信息时仍使用既有通用标题。

## 非目标

- 不修改后端 MCP 协议、事件模型或能力路由。
- 不改变能力执行逻辑、权限流程、结果内容和错误处理。
- 不在标题中展示完整参数 JSON、令牌、凭据或其他内部路由信息。
