# 对话执行反馈与本轮成果交互升级设计

日期：2026-08-24

## 背景

当前对话工作区已经具备消息时间线、流式回复、推理、工具调用、计划、子代理、权限与问题卡片、消息队列、附件、语音、模式与模型选择、成果预览和分屏能力。问题不在能力缺失，而在复杂任务执行时，用户需要从消息区、实时统计、输入框和队列等多个位置判断：Agent 正在做什么、输入会发往哪里、本轮产生了哪些成果。

本设计在现有 `ConversationDetailPanel -> ConversationShell -> MessageListView / ChatInput -> MessageInput` 结构上演进，只调整呈现层和操作反馈，不引入新的永久面板、第二套运行状态或后端协议。

## 目标

- 保留当前工作区、消息时间线和输入框布局，提升复杂任务执行状态的可读性。
- 让发送、等待、流式文字、推理、工具执行、等待确认、恢复和完成形成连续且克制的动效链。
- 在整个 `isPrompting` 周期内，让输入框和右下按钮持续表达“当前对话仍在进行”。
- 保留执行中追加输入、停止本轮、附件、模式、模型、推理强度、语音、队列编辑和分屏等现有功能。
- 在当前 Assistant 回复下方直接展示该轮明确登记的成果，单行最多显示 4 项。

## 非目标

- 不重做工作区导航、Tab、文件区、辅助面板或欢迎页信息架构。
- 不新增任务侧栏、任务画布或新的持久化状态。
- 不修改 `TaskArtifactInfo`、ACP、数据库、Transport 或事件 contract。
- 不用时间窗口、会话累计或文件改动统计推断“本轮成果”。
- 不伪造执行百分比；只有 Agent 提供明确计划时才显示已知步骤数。

## 验收标准

1. 空闲、已发送、执行中、已追加输入、等待确认和完成六个阶段能连续切换，历史消息不会重复播放进入动画。
2. `isPrompting=true` 时输入框显示主题感知的环边光效；右下按钮持续显示三点流动，追加输入成功后仍保持该状态，只有真实回合结束才恢复发送箭头。
3. 停止本轮始终可达：有 live message 时位于实时状态条；首个 live block 到达前也有等价的等待状态条和停止入口。
4. 执行中提交继续走现有 `onEnqueue`，附件、模式、模型、推理强度、语音、队列编辑/删除/排序和 fork 行为不回归。
5. 当前回复成果严格通过该回复内 `present_task_files` 引用匹配；消息下方单行最多显示前 4 项，超过时显示“还有 N 项 · 查看全部”。
6. 文件夹、文件、图片、文档、代码、表格、压缩包和链接具有明确类型；单项复用现有预览，查看全部只包含当前回复匹配到的成果。
7. 窄屏成果保持单行横向滚动；输入框控件不重叠、不换序，分屏和平铺会话布局保持可用。
8. `prefers-reduced-motion` 下关闭循环和位移动画，保留静态状态辨识；键盘焦点、tooltip 和 aria-label 完整。

## 现有组件映射

### 消息时间线

`MessageListView` 继续负责 persisted、optimistic、streaming 三类时间线合并。现有 `MessageEntrance` 和 `CompletionEntrance` 作为唯一进入动画边界：

- 用户消息、Assistant 新回合和首次出现的推理块使用 4-5px 上移加淡入。
- 动画只在活动会话中新内容首次出现时执行；历史加载、切换 Tab 和虚拟列表重新挂载不重播。
- 已完成工具和历史文字保持静止；同一时刻只让当前流式尾句、当前工具或当前计划步骤运动。

### 实时状态条

`LiveTurnStats` 仍是实时状态的唯一展示源，继续使用现有 `LiveMessage`、Plan 和工具块，不复制状态：

- 优先显示当前阶段：等待 Agent、思考中、正在回复或最近的进行中工具。
- 显示已知的计划完成数、耗时、工具数量和后台任务入口。
- 增加停止本轮图标按钮，调用现有 `onCancel`。
- `connStatus=prompting` 但尚无 `liveMessage` 时显示轻量等待状态条，保证停止入口不存在空窗。
- 等待权限、问题或确认时使用现有卡片；状态条停止运行强调，避免多个动画同时争夺注意力。

### 输入框运行状态

`MessageInput` 的 DOM 结构、选择器顺序和现有能力保持不变，仅增加 `isPrompting` 视觉分支：

- 输入框外沿显示单色、主题感知的环行光带；伪元素使用 `pointer-events: none`，不拦截任何控件。
- 平铺会话现有彩色 active-flow 与 prompting 光效不叠加。执行中优先显示 prompting 光效，回合结束后恢复 active-flow。
- 标准 focus ring 保留在内侧；聚焦不会停止或遮蔽 prompting 状态。
- 空输入时保留现有活动占位文案；用户输入后占位消失，但边框和按钮仍持续表达对话进行中。

### 对话中按钮

当前 prompting 分支只显示红色停止按钮。新设计将停止操作移入实时状态条，右下主按钮用于保持发送位置和追加输入语义：

- 空闲/完成：显示现有发送箭头，走直接发送。
- 执行中：持续显示三个流动圆点，tooltip/aria-label 为“对话进行中，加入队列”。
- 有可提交内容：点击继续走现有 `onEnqueue`。
- 无内容、附件尚未就绪或语音占用：按钮保持三点状态但不可提交。
- 入队成功只更新现有队列列表，按钮不变成勾选、不恢复箭头。
- 真实 turn end 后才恢复普通发送按钮。

### 本轮成果

`CurrentReplyArtifacts` 继续使用当前回复中持久化的 `present_task_files` 调用解析结果，并与当前会话成果记录匹配。明确失败或 `Presented 0 task artifact(s)` 继续抑制输入路径回退。

展示规则：

- 仍位于该轮 Assistant 回复的 `TurnStats` 下方。
- 0 项不渲染；1-4 项全部显示；5 项以上显示前 4 项。
- 四个成果位单行横排；窄屏不折行，改为横向滚动。
- 标题显示总数；超过上限时在标题右侧显示“还有 N 项 · 查看全部”。
- 每个成果块显示名称和明确类型。类型由现有 `kind + path extension` 推导，不修改 contract。
- 文件夹使用 Folder 图标；文件继续沿用现有图片、表格、压缩包、文档、代码和普通文件图标；URL 使用 Link 图标。
- 单击成果复用 `TaskArtifactDialog`；“查看全部”打开只含当前回复匹配成果的列表，再复用现有 `TaskArtifactPreview`。
- `missing` 和 `inaccessible` 仍占用真实成果位并显示错误状态，不展示过期预览。

## 响应式与可访问性

- 输入框继续使用现有 container query 折叠模式/模型选择器，新增状态不占用底栏文字空间。
- 成果区桌面为 4 等分；低于可读宽度时保持固定最小项宽并横向滚动。
- 所有图标按钮都有 tooltip 和 aria-label；成果项是可聚焦按钮。
- 动画不改变盒模型，动态内容使用固定或受控高度，避免消息列表和输入区跳动。
- `prefers-reduced-motion` 下环边光效变为静态强调，三点变为静态高对比状态，进入动画关闭。

## 错误与边界

- 追加输入持久化失败时沿用现有草稿恢复和错误提示，不能清空用户内容。
- 回合取消、断连或失败后立即移除 prompting 光效，并由现有 failure banner/错误条接管。
- 用户在等待确认时仍可编辑草稿；是否允许入队继续沿用当前连接与队列策略。
- 查看全部只接受已匹配的当前回复成果数组，不能重新查询会话累计后混入其他回合。
- 成果预览失败继续显示现有 preview error，并保留系统打开/工作区打开等既有动作。

## 实现边界

预计修改：

- `src/components/message/message-list-view.tsx`：把取消入口传给实时/等待状态条。
- `src/components/message/live-turn-stats.tsx`：当前阶段与停止操作。
- `src/components/chat/message-input.tsx`：prompting 样式和持续对话按钮，现有发送/入队逻辑不改。
- `src/app/globals.css`：主题感知环边光效、三点状态和 reduced-motion。
- `src/components/message/current-reply-artifacts.tsx`：单行四项和当前回复查看全部。
- 视文件大小拆出小型展示组件，避免继续扩大已有大文件。
- `src/i18n/messages/{zh-CN,en}.json`：新增状态、入队和成果溢出文案，覆盖当前 checkout 的两个 locale。

不修改 Rust、数据库、共享 TypeScript contract、API、CI、依赖和根配置。

## 验证方案

遵循仓库规则，不默认运行 Cargo/Tauri 构建或测试。验证分层如下：

1. 静态调用链审查：直接发送、prompting 入队、取消、队列编辑、附件、语音、fork、turn end、失败和恢复。
2. 定向 Prettier、ESLint、TypeScript no-emit、locale JSON 解析和 `git diff --check`。
3. 浏览器视觉验证：至少覆盖 1440x900、1024x768、390x844，以及普通单会话和窄分屏宽度。
4. 状态验证：空闲、等待首块、执行中、已追加、等待确认、完成、取消和错误。
5. 成果验证：0、1、4、5+ 项；文件夹、普通文件、图片、URL、missing/inaccessible；单项预览和查看全部作用域。
6. 打包发布前按 release workflow 执行前端构建与仓库既有发布门禁，并独立验证 GitHub 与 Fusion 产物。

## 发布与回退

功能随下一 patch 版本发布，不增加运行时开关。回退只需恢复展示组件和样式；消息、队列与成果数据 contract 未改变，因此不会产生持久化迁移或旧数据兼容问题。
