# 会话用量按需刷新

输出中的本轮统计与会话用量面板，共用按后端 Transport 和会话 ID 隔离的读取器。
原有每次完成后等待 1 秒/3 秒的完整历史轮询已移除。

## 刷新来源

- 沿 ACP 已有事件分发路径接收用量更新、工具完成/失败、回合结束及会话恢复信号。
- 远山原生消息的 assistant/result 作为兼容刷新信号；后台活动仅在有实际历史或完成项时触发。
- 正文、思考增量不刷新历史。首次订阅、页面重新可见和传输重连补读一次。
- 250ms 合并相邻信号，同会话最多同时一个读取，启动间隔至少 1 秒。在途更新合并为一次后续刷新。
- 终态后 1.5 秒补读一次，以容纳原生日志延迟落盘；请求失败、待确认、部分确认或本轮用量暂缺时，
  按 1、3、5、10、15 秒间隔最多补读五次。确认后停止补读，不进行无限轮询。
- 新用量信号抢占重试等待，并重置有限重试预算；不必等上一轮退避定时器到期。
- 隐藏页面停止读取，所有订阅移除后清理定时器和快照。新会话/新回合使在途旧结果失效。

## 统计与兼容

继续使用既有 get_folder_conversation、历史解析器和后端消费核对，不新增后端接口或字段。
上下文事件中的 used/size 仅作为刷新信号，不能当作分类消费 Token。

本轮元数据合并和界面连续回复合并均保留 confirmed_points；金额沿用 18 位十进制合并，
同一原生回合只使用后端挂在末尾消息上的账单，保留待确认、部分确认和已确认状态。
按用户最新展示要求，没有后端金额时使用现有模型报价与记录的互斥 Token 分类估算；
界面统一只显示点数数值，实际账本到达后优先采用后端金额。估值与账本独立，不写入扣点记录，
不修改账户余额。报价或用量不足时显示统计中，不显示预估/已确认前缀和“已上报用量”。
星河与远山也启用原后端报价路径；账本与报价查询并行，历史缓存的估值按当前登录账号目录重算。

回复结束后，已知 Codex 会话的元数据首次在 250ms 后补读；账单尚未确认时沿用上述
五次补读预算。其它代理保持首次 1.5 秒、最多额外补读一次且间隔 3 秒；尚未获得代理
类型时先采用该时序，读取后再按真实类型重试。取消或切换后端后丢弃在途结果。

## 消费账单本地缓存

Codex 账单查询先批量读取 SQLite 的 app_metadata；每个请求一个带版本的缓存条目，
键由网关地址、当前账户登录令牌的 SHA-256 摘要及 request_id 组成，不保存明文凭证。
账户正常续期不改变访问令牌，应用重启继续命中；切换登录身份或网关后使用独立缓存。

后端返回请求终态账单后，在同一事务内保存该请求的所有 stage；金额使用原始十进制
字符串。再次打开、翻页或重启应用时不再向网关获取已缓存账单。终态的部分用量及
不可计费状态也保留原状，不能重新按当前价格估算；未确认或空记录不永久缓存。

仅缺失或 pending 的请求进入远端查询，每批最多 100 个 ID，单轮总预算 5 秒。
并发读取通过同一互斥锁复用查询结果；pending 在响应后至少间隔 1 秒再查，失败
至少间隔 3 秒再查。缓存读取和写入异常记录原因，内存缓存继续复用已拿到的账单，
后续读取可重新尝试落库，无需重复请求远端。

本轮用量仅在后台已关联 in_flight_user_turn_id 后显示；尚未关联时保持等待，避免将
上一轮消费展示在新回复上，也避免使用远程客户端时钟判断服务端历史的时间。
跨页时检查外部会话、当前用户边界、历史条数和累计 Token 一致性，变化时放弃部分结果。
只打开会话面板时读取尾页统计，不为本轮用量额外翻页。完成后的统计仍沿既有历史同步补齐。

读取完成仅保留轻量用量快照，不缓存完整正文和工具输出。旧运行时缺少用量更新事件时，
工具和回合结束仍会更新；后端用量统计不按流式 Token 逐个刷新。回复生成期间，前端会按
当前输入、正文与思考文本和模型目录价格更新点数；后端分类用量到达后扣除已上报 Token，
账单确认后优先展示后端金额。缺少无歧义价格或分类明细时不显示不完整估值。

## 验证与限制

按仓库规则进行静态审查、TypeScript 无输出检查、定向 ESLint、Rust 编译检查和差异检查，
未新增或运行测试，未启动或打包桌面端。真实账单落盘及重启后的产品流程仍需运行时验证。
此次消除无变化时的定时读取，并合并两个展示入口；发生用量变化时仍沿用完整历史解析，
不代表所有原生格式都已实现增量解析。
