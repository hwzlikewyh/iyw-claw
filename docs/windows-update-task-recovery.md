# 更新等待与任务恢复

2026-11-24 故障日志中的 `Active tasks must finish before updating` 表示任务门禁阻止更新。
旧界面将它显示为“安装更新失败”，虽然更新包已下载并校验成功。

## 行为

- 更新被阻止时区分 Agent、自动化、语音、终端和待确认状态。
- “任务完成后自动更新”是当前发布的一次性预约。关闭更新弹窗不会取消，用户可取消本次预约。
  预约不依赖全局静默更新设置或窗口失焦，任务门禁解除后自动安装并重启。
- “强制重启更新”先准备更新包和安装器，再保存并暂停可恢复的 Agent 会话。
  重启后恢复原 session、项目及配置，向原会话提交一次继续未完成任务的持久化输入。
- 普通的立即更新保留任务门禁。服务端和远程桌面沿用原更新接口，不支持这些本地桌面策略。

## 恢复边界

强制更新支持已建立可恢复 session 的普通 Agent 会话。已完成、已删除、明确取消的任务不重启。
正在等待用户确认、原生独立后台回合、宿主委派子任务、渠道任务或没有恢复能力的 Agent，
在暂停之前给出明确提示；这些任务应完成后再更新。自动化、实时语音和交互终端也保留门禁。

恢复是继续原会话的未完成目标，不是恢复操作系统进程内存。续跑指令要求先核对工具结果及
产物，结果不确定的外部操作不能盲目重发。安装器准备失败不暂停任务；暂停或后续交接失败时
尝试恢复已暂停的会话。暂停仍未结束时保留记录并提示，而不是在原任务仍执行时重复提交。

## 实现与一致性

- `update/manual.rs` 与 `manual_wait.rs` 负责一次性策略，复用共享更新状态、签名校验和安装器交接。
- 等待使用独立预约 ID；取消再预约不会让旧等待流程领取新预约。安装前重新验证发布身份。
- `acp/update_tasks.rs` 在操作门禁内快照活动会话并发送取消协议，不调用用户取消入口修改授权意图。
- 新操作与持久化输入派发均受原 ACP 操作门禁约束；暂停期间队列保持等待。
- Windows 安装器交接等待父进程退出的上限为 60 秒；整批任务暂停最多等待 15 秒，为正常退出留出时间。
  超时会退出本次交接，保留恢复记录并尝试恢复已暂停任务，不逐个累计超时。
- `inventory/update-task-recovery.json` 以临时文件、同步写入及原子替换保存，不存储凭据或原始提示词。
- 每个续跑记录使用固定输入 ID，经现有 outbox 幂等派发；接收确认前不删除恢复记录。
  结果未知、任务仍在执行、会话恢复失败时保留记录并在更新界面提供诊断和重试。
- 用户主动停止会话时撤销该会话的更新恢复记录和尚未派发的续跑输入。
- 恢复状态由后端管理，多窗口和重复重试不能创建多份恢复操作；启动恢复复用原生 session 去重锁。
