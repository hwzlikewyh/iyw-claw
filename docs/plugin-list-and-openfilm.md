## OpenFilm 打开入口

OpenFilm 0.3.5/0.3.6 已包含 CLI 和 Studio，但插件清单没有标准 MCP App 声明。桌面端为已安装的 `iyw-openfilm` 提供兼容入口，只有 `bin/openfilm.mjs` 和 `studio/ui/dist/index.html` 存在时才列为可打开的应用。

点击“打开”会校验安装版本、可用状态及包内文件路径，使用受管 Node 执行已有 CLI 的 `open` 命令，再把返回的 Studio 地址放到当前窗口的内置浏览器。若已有对话，则使用它的工作目录；无对话时使用按账号隔离的独立 Studio 目录进入项目列表，不创建对话记录。用户发送消息时仍由原有流程创建对话。此命令不请求创建新影片目录。

启动时设置 `OPENFILM_NO_BROWSER=1` 和 `OPENFILM_NO_UPDATE_CHECK=1`，关闭 CLI 的系统浏览器回退和更新检查。仅接受带会话 key 的 `http://127.0.0.1:<port>/open` 地址，不在日志中记录该地址。Windows 下去除 Node 不支持的扩展路径前缀，并再次确认实际文件与已校验的入口相同。

Studio 的兼容入口仅面向本地桌面运行；服务端模式不提供这个列表项。标准 MCP App 继续使用原有的授权、启动和面板生命周期。
