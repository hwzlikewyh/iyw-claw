## 验收标准

1. 目标内容完整可读、独立于工具记录，不再二次折叠正文和思考。
2. 普通对话、目标和循环共用事件到达顺序：思考、阶段正文、工具、新思考、后续正文原位追加。思考流式时展开，内容结束后只自动收起一次；手动重新展开后不反复合拢。只收纳连续已结束工具组，不跨正文或新的思考重新归组。
3. 持续工作和等待调度使用不同动效；等待用户、断线、完成停止工作动效。减少动态效果、隐藏页和当前进展不可见时暂停。
4. `/goal` 与 `/loop` 区分持续目标和周期调度，不按前端时钟生成轮次、阶段、执行成功或消费。没有循环触发关联回执时，只展示会话活动。
5. 控制遵守当前原生能力：星河目标暂停/恢复/清除；远山目标清除；循环取消填写待发送请求，确认前不改变调度状态。暂停目标与中断当前回复独立。

动效补充核对：连续重播会取消上一动画帧；首帧时间差按非负数处理，避免极快重播时出现无效阶段。浏览器中连续重播八次后仅保留一个播放循环；运行时开启减少动态效果会停止时间线与 CSS 动画。最新录制含结尾停留共 49 秒。

## 现有问题与建议

`groupGoalRuns` 将 create_goal 之后、update_goal 之前的正文、思考、工具全部收进 `goal-run.items`；`GoalCard` 除错误外默认收起。外层 `splitAssistantTurnParts` 仅把最后一段顶层 text 当正文，其余内容进入过程。于是目标卡片包裹的正文/思考被第二层折叠，用户在外层过程里只能看见目标标签。

备选方案：继续扩张目标卡片会延续双重折叠；为目标新增独立工作台会割裂当前对话。推荐保留现有对话框：顶部一个精简任务条承载目标、调度及原生控制，正文和可见思考留在对话中，工具按实际用户/模型轮次收纳。历史不默认堆叠所有工具行，最新工具与方向直接可见。不得把多轮正文合并成仅末尾一句。

产品实现时优先复用 ConversationPresentationProvider、运行时任务注册表、现有消息适配器和可见性上下文。需把 goal 包装中的内容恢复到原顺序，而不是删掉 create/update 事件或增加并行消息存储。图像、计划、权限/提问、子代理和监听保持原生特殊渲染路径。完成前回查实时、历史、恢复和连续目标分组行为。

状态仅由后端原生事件决定。运行状态文案不承诺“工作正常”，也不以无输出时长推测断线；断线独立明显显示。loop 的下次计划时间仅在原生有值时显示，计划时间到点后依然等待回执。当前固定 SDK 不提供完整触发周期关联，预览不把会话活动伪称为第 N 次 loop 执行，也不按时间分摊消费。

动效采用同一当前状态处的三条竖线节奏、文字轻微流光以及工具活动线，不给正文整块闪烁，不放伪进度百分比。等待调度只留低频圆环；工具活动线与工作条停止于静态/断线状态。预览秒数是演示时间，不代表真实计费或后台健康证明。

## 参考资料与边界

- [WorkBuddy 任务对话](https://www.codebuddy.cn/docs/workbuddy/Conversation)：同一对话保留回复、执行阶段、结果摘要和可展开步骤；执行中补充消息、队列编辑与继续推进。已读取官方执行进度截图 `conversation-exec-progress.DHoekDQp.png`，其中正文、进展和工具阶段分开显示。
- [WorkBuddy 任务管理](https://www.codebuddy.cn/docs/workbuddy/Task-Management)：进行中、待处理、完成及侧栏提示分开。
- [CodeBuddy goal](https://www.codebuddy.cn/docs/cli/goal)：独立目标状态条、继续推进/达成/不可达反馈。官方实现语义仅作设计参考，不把其 Web UI 暂停能力映射为当前远山 SDK 能力。
- [CodeBuddy loop](https://www.codebuddy.cn/docs/cli/scheduled-tasks)：调度、等待空闲、触发记录与最近执行状态分开；按时间重复与目标达成条件不同。
- [Claude Cowork 周期任务](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork)：按计划运行，查看未来/过去执行与单次结果。其云端能力不代表本项目会话调度能力。
- [Claude Cowork 入门](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)：执行阶段反馈、可见 reasoning/approach 与中途引导。仅借鉴交互层次。
- [Vercel AI Elements Reasoning](https://elements.ai-sdk.dev/components/reasoning)：明确提供流式时展开、结束收起、手动展开和限高内容。只采用其折叠生命周期，不照搬把所有 reasoning 聚合到正文之前的示例，避免打乱思考/工具/正文交错的原始顺序。
