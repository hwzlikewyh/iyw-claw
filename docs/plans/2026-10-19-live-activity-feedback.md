# 对话实时状态反馈调整

在已确认的第十二版界面上，按本轮截图反馈定向调整。沿用现有宿主事件、消息镜像、会话活动订阅与可见性上下文，不变更后端协议或计费口径。

## 验收

1. 过程摘要移除“包含错误”和红色错误图标，具体工具结果继续在过程记录中呈现。
2. 当前状态放在原助理名称旁边；新工具、思考、正文和重试事件及时更新，不因 5 秒没有新分片就抹去最近处理阶段。等待时显示最近工具步骤和经过时间，不虚构进度或预计完成时间。
3. 等待文字柔和明暗变化，完成、断线或等待用户确认时停止；隐藏页面和减少动态效果时暂停。顶部可见时不重复播放底部状态动效。
4. 展开过程固定高度：桌面 320px、窄屏 240px；内部可滚动且隐藏滚动条，保留键盘访问，收起按钮位于滚动区域外。
5. 从发起消息到首个响应，按现有连接/提交状态显示初始化环境、发起对话和等待模型响应；不使用时间模拟阶段推进。
6. 点数统一仅显示数值，不显示预估/已确认、来源说明或“已上报用量”。有后端金额时优先使用；缺失时复用后端既有报价估算，分类用量或无歧义费率缺失时显示统计中。缓存中的估值按当前账号报价重新计算，不写入账本。
7. 上下文压缩摘要通过独立弹层查看，使用原有 Dialog 焦点/关闭行为，避免内容受过程视口限高裁切。

## 步骤 → 验证方式

1. 状态与摘要接线（完成） → 静态复核真实事件、会话隔离、最新操作、重试和等待用户输入分支。
2. 名称旁状态、等待动效和过程视口（完成） → 复用 use-stick-to-bottom，自动跟随新过程但用户上翻后不抢滚动；桌面/窄屏限高并受可用窗口高度约束。
3. 点数与压缩摘要（完成） → 保留后台消费及账号隔离；报价与账本查询并行，纯数值展示；摘要使用 Dialog Portal 独立呈现。
4. 静态检查与交付（进行中） → 已通过 TypeScript、定向 ESLint、Prettier、翻译参数与 diff 检查；已用本机已有 stable rustfmt 只解析 Rust 语法，不编译。合并主分支后再次检查集成结果并提交远程构建。

按仓库规则不新增或运行应用测试，不在本机编译、打包或启动桌面；实际点击、渲染动效与智能体实时消息流程仍需安装新版后验收。
