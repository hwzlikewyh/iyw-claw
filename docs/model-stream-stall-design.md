# 模型流无响应收敛设计

## 2026-10-29 历史图片切模故障补充

用户已授权提交、推送并合并远程主分支；后端由用户自行发布，本轮不触发安装包或容器发布。

正式请求确认：PC 发送受管图片引用后，未开启 URL 的候选在 Fusion 还原原图，
40 图约 66 MB 的请求响应头超时后被重试 6 次，累计约 752 秒。
该链路与会话恢复是否成功独立；单纯恢复对话或切换选择器无法解决图片传输能力差异。

本轮沿通用渠道能力协商修复：图片扫描、去重、缓存、直传和字段替换仍由本地网关处理；
批量解析失败不清除未过期的已确认能力，缓存命中的图片继续本地改写，仅缺失 ID 交由云端。
不新增模型名特例，不凭 HTTP 200 判定 URL 识图成功，不改变原图或绕过资源所有权。

Fusion 文本流的首内容等待改为累计最多 120 秒，覆盖图片准备、上传、候选重试和提交前探测。
快速可恢复故障在剩余预算内仍按既有规则重试；真实内容出现后保留长流及工具后续流程。
运行时还可能有限重试多个 Fusion 请求，不能将该服务端预算描述为完整用户回合时限。
非流式/图片生成预算保持原流程。本节优先于下文早期的“响应头超时一律停止候选重试”说明。

## 背景

2026-09-28 日志记录了 Responses 流在 `response.completed` 前关闭、非法 UTF-8、
`max_output_tokens` 截断，以及 600 秒静默后才安全取消的情况。当前 Codex 采样重试上限
由 provider 提供，日志中为 10 次；Fusion 同协议流已逐块透传、关闭 Nginx 缓冲并每
5 秒发送 SSE 注释保活。

## 用户确认的范围

- 保留模型和上游选择；超时不切换模型或服务商。
- 不增加服务端熔断。
- 收敛同一模型请求的重试和静默等待，让等待与终止状态对用户可见。
- 保留长时间活动工具的声明超时、已打开 SSE 流的长任务以及既有协议终态语义。

## 设计

### iyw-claw

- Codex sampling 的最大重试次数限制为 3，仍使用当前已选模型/服务商；不重放已
  完成的工具调用，不改变压缩、登录或其它非 sampling 重试策略。
- ACP prompt 默认静默阈值为 600 秒（10 分钟）。2026-10-12 根据用户反馈，将此前的
  120 秒阈值放宽，避免慢请求或有限重试尚未结束就被外层取消。既有活动工具超时预算
  继续覆盖基础阈值；环境变量覆盖和 `0` 禁用语义不变。
- 将重连事件作为一个可更新的非终态提示显示，并在回合结束时清除；静默超时发出安全
  取消请求时显示提示。不得把底层原始响应正文或凭证展示给用户。
- `max_output_tokens` 是输出上限，不当作连接故障重放；识别固定 Codex pin 的输出上限
  原因后停止该请求重试，并映射到已有的最大 Token 提示。非法 UTF-8 和缺少
  `response.completed` 仍按流错误处理，最多重试 3 次。

### iyw-fusion-api

- 对流式请求的响应头等待和首个真实内容等待分别取现有配置与 120 秒上限中的较小值；
  非流式预算不变。
- 响应头等待超时返回现有错误响应并停止该请求的候选重试，不选择其它模型或上游。
- 首个真实内容出现后不设置整流总时限，继续沿用现有空闲预算；已有 5 秒 SSE 注释保活、
  字节透传、客户端取消和 terminal-event 检查保持不变。
- 现有 SSE reader 按字节累积事件，已有回归覆盖 UTF-8 多字节字符跨 chunk。中转层不
  把流整体转成字符串，也不尝试修复上游畸形字节；客户端在有限重试耗尽后显示明确失败。

## 验收

- Codex sampling 最多重试 3 次；响应头超时不触发模型/服务商切换。
- `max_output_tokens` 不进入网络重试循环，用户收到已有最大 Token 提示。
- 无活动工具的静默回合在约 600 至 630 秒内发起安全取消；活动工具仍按声明超时保护。
- Fusion 等待响应头或首个真实内容超过 120 秒时不切换候选并返回清晰错误；首内容出现后，
  长 SSE 流超过 120 秒仍可正常完成或由自身空闲预算结束。
- SSE 回归保留中文 UTF-8 分片、断流缺少 terminal、保活和客户端取消覆盖；有限重试后
  畸形 UTF-8 以终态错误结束，不伪造成功。

## 2026-10-29 大上下文压缩失败降级

会话 803 的 70.5% 上下文约 703K/997.5K tokens。压缩请求正文约 1.1 MB，
Fusion 返回 HTTP 200 但没有首个有效内容，客户端重复重试后才失败，且历史始终没有被替换。

当压缩请求属于可重试的流错误，且本次输入仍低于模型硬上下文窗口时，保留原历史并继续发送本回合，
不把压缩失败升级为整回合失败。同一模型的再次压缩按 100K token 阶梯延后，达到硬窗口前才重试；
模型切换或压缩成功会清除延后状态。压缩请求总预算为 180 秒，避免重复等待数分钟。

如果当前输入加历史已达到硬窗口，仍返回原有上下文错误；不会在超出模型硬限制时盲目发送请求。
