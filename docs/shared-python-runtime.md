# 共享 Python 环境

普通脚本和兼容的技能依赖默认使用 `~/.iyw-claw/runtime/envs/python`。环境由应用初始化、环境安装引导或修复入口使用受管 uv 创建，固定 Python 3.13；uv 的解释器与下载缓存继续使用现有共享目录。重复初始化直接复用，任务启动不创建环境、不安装包。

## 选择与安装

- `IYW_CLAW_PYTHON_ENV` 提供环境根目录，`IYW_CLAW_PYTHON` 和内置提示给出解释器绝对路径。Windows 使用 `Scripts/python.exe`，其他系统使用 `bin/python`；共享目录不强行前置到全局 PATH，以免覆盖项目的 `.venv`。
- 通用脚本使用该解释器，缺少依赖时执行 `uv pip install --python <共享解释器> <包>`，不对共享环境执行会删除其他任务依赖的 `uv sync` / `uv pip sync`。
- 项目已有 Python 环境、版本约束、依赖与锁文件时，遵循项目入口。宿主不全局注入 `VIRTUAL_ENV`、`UV_PYTHON` 或 `UV_PROJECT_ENVIRONMENT`，避免覆盖 uv 的项目环境发现。
- 已激活的项目环境应保留 PATH 优先级。需要不兼容依赖或不同 Python 版本时，在共享 `envs` 目录下建立具名专属环境，后续继续复用。
- 安装器若内部创建环境，优先使用它支持的环境参数；强制隔离的安装器保留专属环境。浏览器下载按其版本复用原缓存。

## 生命周期与边界

独立环境安装引导在 uv 激活后准备共享环境；桌面 Tauri/Web 初始化入口兼容旧安装，服务端初始化入口也负责准备。只读状态查询和普通命令执行均不触发下载。

创建过程用文件锁避免多个应用实例并发写入，最多等待 10 分钟，每 15 秒上报等待状态。创建后实际启动解释器检查版本与虚拟环境身份。完整安装或修复会验证已有环境；已有环境损坏或首次创建留下非空半成品时保留文件并报告错误，不自动清空已安装依赖。独立环境安装引导只记录准备错误；应用初始化在后台准备共享 Python，立即放行 Agent，错误只写 warning 和进度消息，不把受管 uv 标记为失败。Agent 在任务需要 Python 时检查状态和日志并自行修复。初始化诊断保留在 `runtime/envs/.python-setup.log`。

Windows 7 不支持这里选择的 Python 3.13，跳过默认环境创建，保留其专用运行时路径。共享环境不属于 Fusion 分发组件文件清单，任务增量安装依赖不会触发组件完整性修复。

## 实施与验证

1. 明确初始化和命令环境入口 → 对照现有环境引导、桌面/服务端初始化与 Agent PATH 调用链。
2. 接入持久环境与使用规则 → 检查重复调用、文件锁、错误返回和项目环境优先级。
3. 定向验证 → Rust 格式与编译检查、静态调用链审查；按仓库约定不新增或运行测试。

uv 官方说明：<https://docs.astral.sh/uv/pip/environments/>、<https://docs.astral.sh/uv/reference/cli/#uv-venv>。`VIRTUAL_ENV` 优先于目录中的 `.venv`，因此只提供宿主环境路径及显式安装命令，不全局激活共享环境。
