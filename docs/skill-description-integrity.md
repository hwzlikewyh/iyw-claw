# 旧技能 description 兼容与完整性校验

## 问题与范围

2026-10-24 定位到供应商调研场景 `scene-supplier-research@1.2.0`
无法启用：旧技能补齐顶层 `description` 后，文件树摘要与原始安装记录不同。
两个依赖包均已安装且摘要一致。仅在内存移除补齐的那一行后，场景包摘要
即可与原始安装记录完全匹配。

原先启用流程在 `requested_enabled=true`、`effective_enabled=false`、
`actual_enabled=false` 时仍返回 `in_sync` 且不返回阻断原因，前端只能显示
笼统的“技能包或依赖未能对当前 Agent 启用”。

## 修复与验收

1. 优先严格比较真实文件树摘要；一致时保持原路径，不额外扫描。
2. 摘要不一致时，仅在内存撤销紧跟 frontmatter 起始行的 `description`，
   再运行现有兼容补齐函数；其输出必须与当前文件逐字节相同。
3. 使用恢复后的入口和全部其他文件重新计算完整文件树摘要；必须与原始
   安装记录匹配。正文、其他元数据、依赖内容和附带文件的修改继续阻断。
4. 保留真实内容摘要用于冲突检查，不改写安装记录或磁盘上的技能文件。
5. 启用被阻断时返回既有 `error` 字段和 `out_of_sync`，日志记录实际、
   有效启用状态和具体阻断原因，不修改 API 字段。

## 交付验证

- 四个修改的 Rust 文件通过已安装 stable 工具链的 `rustfmt --check`。
- `git diff --check` 通过；调用链静态审查覆盖正文、description、附带文件、
  换行格式、异常输入和启用阻断分支，未发现需要扩大改动范围的问题。
- 真实供应商技能只读复核：补齐往返逐字节一致，恢复后摘要与安装记录一致；
  未修改本机技能或安装记录。
- 按用户要求中止 `cargo check`，不再编译，未取得完整编译结果。
- 按仓库约定不新增或运行测试套件；未重新打包或安装客户端，桌面端实际启用
  流程尚未实测。
