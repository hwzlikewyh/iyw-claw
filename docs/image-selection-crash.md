# 选择图片闪退修复

0.1.271 的现场日志在图片分块上传开始后中断。150 KB JPEG 的临时文件已经完整写入，
进程退出时没有 panic-hook 记录。图片复用新增异步分支放大了图片准备及 Tauri 调用方的
Future；已安装 Windows EXE 的上传完成命令包装栈帧为 68 KB，旧备份为 14 KB。

共享图片准备入口改为返回装箱的 Future，网络上传分支和分块上传完成操作也装箱。
权限检查、撤销、原图片传输、结果结构及临时文件清理沿原链路执行。新增完成入口、
准备开始、完成/失败日志，不记录图片正文、Base64、token 或完整图片 URL。

实际桌面验证还发现星河初始化的 `app_server` 阶段线程栈溢出，退出码为
`0xC00000FD`。原生调用栈显示配置加载、权限合成和新建会话多条链路都会叠加栈帧，
仅对某个调用边界装箱不能完整解决。Windows 桌面沿 Tauri 官方 async_runtime::set
扩展点注入 Tokio runtime，将线程栈设为 8 MiB，生命周期由静态 OnceLock 持有。
工作线程数量和其它平台保持原默认，取消、任务调度和配置流程仍走原 runtime。
没有设置进程级 RUST_MIN_STACK；排查时的上游改动已移除。

## 多轮图片保留

支持视觉的模型会在后续回合保留历史图片；工具输出正文裁剪也保留 InputImage。
图片复用关闭时继续原传输。内置星河沿已保存的 rollout 恢复原输入，不依赖前端
再次附图。压缩会改变活动上下文，已支持的资源 ID 保留在摘要中，可用 view_image 回读。
