# 数据库性能与兼容性

2026-09-19：保留 SeaORM + SQLite、现有持久化配置和旧接口，优化读写路径。

## 已实施

- 独立迁移 `m20260919_000001_crud_indexes` 新增 6 个索引，覆盖全局/根会话/文件夹排序、自动化关联、日志及自动化过期清理。新复合索引覆盖原 `folder_id`、`parent_id` 单列索引，因此迁移移除这两条冗余索引；回滚会恢复它们。
- 会话状态、置顶和软删除使用直接 UPDATE，保留不存在错误、软删除过滤、CAS 和原有时间戳语义。
- 导入每批 32 条，在事务中按 `(external_id, agent_type)` 查重并批量插入；保留手工标题、删除状态和导入计数。瞬时锁冲突沿用现有事务重试。
- 标签页每批插入 100 条，沿用原有 CAS 锁、事务、草稿过滤和首个活动标签优先规则。
- 全局列表通过 SQL 子查询筛选有效文件夹，通过索引支持的 NOT EXISTS 排除自动化会话；子会话计数每批最多绑定 500 个 ID。
- 日志、自动化历史每批最多清理 200 条，每轮最多 2,000 条，批间暂停 25ms。积压达到轮次上限时，5 秒后继续下一轮；清理完成后恢复原有日常周期。运行中自动化记录不删除，关联会话隐藏与 run 删除保持同批事务原子性。
- KV 读取仅选择 value，减少无用列的读取和模型构造。

## 分页与兼容

新增 POST `/api/list_conversations_page` 和同名 Tauri 命令。两端参数均为 `{ "params": { ... } }`，params 使用 camelCase，响应为 `{ "items": [...], "next_cursor": ..., "incomplete": false }`。

支持 `folderIds`、`agentType`、`search`、`status`、`sortBy`、`includeChildren`、`cursor`、`pageSize`。默认每页 100 条，上限 200，页大小 0 会收敛到 1。

游标按数据库实际的 `updated_at` 排序文本与 ID 前进，保留旧时间格式和小数精度。客户端必须原样传递游标，不能重新格式化时间。`oldest` 为升序，其他排序值沿用更新时间降序。过滤条件或排序改变时重新从第一页开始。

`updated_at` 可被实时事件修改，分页不提供跨请求数据库快照；并发改动后重新查询可取得最新顺序。

命令搜索使用新分页，提供前后页导航。一次搜索最多检查 1,000 个候选会话，沿用原有可见正文和隐私过滤；即使当前批次没有命中，只要 next_cursor 存在，仍可继续查找后续历史。历史读取失败通过 incomplete 显式呈现，并允许重试或继续翻页。

旧服务端不认识新命令时，前端仅对 HTTP 404 或明确的命令不存在回退旧接口。数据库、认证和网络等其他错误不隐藏。

旧 `list_all_conversations` 仍完整返回。主侧栏、会话管理、引用选择和用量统计依赖这个完整集合，本次保留其数据语义，未将其静默截断为最近 100 条。它们受益于索引和 SQL 优化，但完整结果的内存与传输量仍随历史增长。进一步全量替换需要独立完成分组分页、置顶/活动会话定位和服务端全局统计。

标题刷新仅在分页起点运行，后续页不重复执行全库标题刷新。尚未增加 Codex 标题文件增量缓存或正文 FTS 派生索引。

## 隔离性能测量

环境：本机 Node 24.18.0 内置 SQLite，临时磁盘库，WAL + NORMAL，32 MiB 页缓存、64 MiB mmap。代表性 schema 使用 100 个文件夹、10% 软删除记录和约 1/17 的自动化关联；生成 10 万、100 万条会话及日志。执行实际新增迁移 SQL，每项预热一次、测量 15 次，并检查优化前后的返回 ID 完全一致。

下面是最终索引组合的 SQL P50，单位 ms。它们不包含 Rust ORM、标题文件同步、网络、正文解析或前端渲染，不能作为整应用提速倍数。测量未清空操作系统缓存，也不是独占硬件的生产压测。

| 查询 | 10 万：改前 / 改后 | 100 万：改前 / 改后 |
| --- | --- | --- |
| 最近 100 条根会话 | 39.796 / 0.154 | 482.368 / 0.174 |
| 文件夹内 100 条会话 | 4.272 / 0.101 | 12.247 / 0.103 |
| 时间游标深页 100 条 | 28.019 / 0.118 | 361.300 / 0.215 |
| 定位 200 条过期日志 | 4.135 / 0.067 | 41.506 / 0.070 |

百万条下，四项改后 P95 分别为 0.240、0.128、0.248、0.370ms。EXPLAIN 确认使用目标复合索引，消除了这些查询的临时排序及自动化历史全表扫描。

简化写入路径每样本 320 条：原索引下逐条自动提交 P50 为 807.000ms，最终索引下每 32 条一批的插入为 9.414ms。只更新 status 列的同配置对比为读取-更新-回读 4.569ms、直接更新 1.083ms。该更新测量未包含 updated_at 变化引起的索引维护，不能作为实际会话状态更新延迟；插入测量也不等同于含文件解析的实际导入吞吐。

新增索引有成本：相同逐条插入方式的 P50 从 807.000ms 增至 877.484ms；批量写入 P95 可因 checkpoint 出现波动，本次为 521.992ms。不能保证每种单条写入都加速。百万条样本的建索引和冗余索引移除约 7.7 秒，生产库首次升级时间取决于数据和磁盘。
