# 持续任务、子代理与消费核对

任务状态来自宿主保存的原生事实，输入框的命令选择只表示待发送配置。
父回复结束不会清除仍活跃的任务。桌面和服务器共用运行时注册表及业务入口。

## 状态与操作

| 能力 | 状态来源 | 操作语义 |
| --- | --- | --- |
| 星河目标 | 原生目标快照，读取内部真实 goal_id | 原生暂停、恢复、清除；不暗示当前回复已经中断 |
| 远山目标 | SDK active_goal 及已确认的原生目标快照 | 当前版本只提供清除，不能伪造暂停/恢复 |
| 远山循环 | SDK 的 CronCreate、CronDelete、CronList、ScheduleWakeup 结构化结果 | 取消入口填写原生工具指令，发送并收到工具结果后才改变状态 |
| 星河原生子代理 | 已验证父子线程的原生启动、回合及输出事件 | 定向中断本轮；不会冒称关闭整个代理 |
| 远山原生子代理 | SDK task 生命周期及 Agent/Task 结构化结果 | async_launched 只表示已启动；没有原生能力时不显示直接停止按钮 |
| 远山后台任务 | 协商 AIR asyncTasks 后的 canStop 与状态通知 | 只对运行时明确允许的后台任务调用停止接口 |
| MCP 委派 | 既有委派注册、子连接与结果 | 复用子会话详情、权限/提问处理和定向取消 |

持续任务控制使用独立命令通道，不进入普通消息队列。控制前校验可用的原生任务身份，
目标操作遵循原生的“当前目标”语义。控制超时表示结果未确认，不自动重放。
远山 ACP 会先发布乐观的目标快照；宿主不将这种预告当作目标生效或已结束。
清除请求只有接收回执而没有原生目标确认时，显示待同步；旧控制响应也不覆盖后来的生命周期事件。
子代理补充指令通过主代理转达，不将填写草稿描述成消息已送达。

星河原生子线程的权限/提问共享父界面的交互入口，但保留子线程 admission token、
目标和回合身份；回传给原始子线程，并校验其父子所有权。父界面能看到子线程来源。
原生子代理详情复用现有会话解析器和执行记录对话框；远山只读取确认过的 agentId，
不会使用任意 output_file 路径读取文件。只有打开详情时才刷新完整执行记录。

任务头和原生子线程计费身份存入既有 app_metadata，不修改数据库结构。
旧活跃任务恢复后标为待同步并清空操作；不把持久化的 running 当作当前存活证明。
展示历史最多保留 100 个终态任务，计费父子身份独立保留，不随展示裁剪。
会话身份切换前保存旧任务快照，并重置当前会话控制域。

## 消费口径

- 消费取 Fusion `actual_points`；账本扣点取 `charged_points`，与结算状态分开显示。
- 消费全程以最多 18 位小数字符串传递；Rust 按十进制数位、前端按 BigInt 精确求和。
  集合金额可超过数据库单行 DECIMAL(38,18) 上限，不使用浮点或 Token 估算补齐。
- 基本唯一键为 `request_id + stage_key`。会话为自身与后代请求集合的并集，
  主代理自身排除原生子请求及独立子会话。跨页和同一原生回合重复展示仍按集合去重。
- 星河私有回执在请求发出前读取真实 goal_id，保存 root_turn_id；目标文字和创建时间
  都不充当目标身份。同一回合出现多个目标时，不凭回合时间猜测子请求归属。
- 远山使用 SDK request_id、原生消息 ID 和 parent_tool_use_id；Fusion Messages 响应头
  返回自身账本请求 ID。Agent/Task 工具及嵌套调用按真实工具关系归属。
- 不完整消费显示 partial；账本未落库显示 pending；无法确认显示 unavailable。
  缺少任一扣点金额时，汇总扣点保持 null，不能补零。
- 消费缓存按服务域、账号会话、企业空间及凭据摘要隔离。显示身份不随正常令牌续期改变，避免续期后同一账户的轮次被错误拆开。
  只读账单不要求存在可消费余额。持久缓存只保存消费字段，可变结算有界补读。
  切账号/工作区时清空所有显示金额并使旧异步读取失效，不清除对话正文。
- 详情可查看完整原值及请求阶段；最终显示舍入不参与费用求和。

## 已知能力边界

远山 0.73.0 的目标快照没有公开唯一实例 ID；部分压缩、重试请求也没有 SDK 请求回执。
这些范围明确显示待核对或部分确认。循环触发没有可靠的请求级实例关联时，不按时间、
提示词或最近一次循环来分摊费用。没有请求回执的其他类型委派同样使会话统计保持部分状态。

循环状态是最近一次原生工具确认的调度状态；当前 SDK 没有暴露完整的循环触发周期事件，
不能据本机时钟伪造“本轮已开始/已结束”。未知状态通过同步及原生列表结果恢复。
当前运行时没有宿主直接取消 cron 的接口，界面明确要求发送取消草稿并等待确认。

“消费已确认”只表示选定、已关联请求的消费已核对，不代表外部批扣成功，
也不代表未上报的请求可以忽略。账本分配的整数值不能与小数消费直接比较。

## 验证与发布验收

本机按仓库规则不新增/运行客户端测试，不编译或启动桌面。执行 TypeScript 类型检查、
定向 ESLint、Rust 按对应 edition 的语法解析及 diff 检查。静态审查覆盖能力协商、
双模式路由、追加指令、原生身份、父子权限回传、超时不重放、恢复、账户隔离、精度和去重。

Fusion 执行正式定向/全量 Go 回归、三协议非流式/流式 smoke、vet 和 build。
没有查询正式数据库、调用真实模型或执行真实扣款。

发布环境必须继续验证：目标自动续跑时追加/暂停/恢复/清除；循环创建、触发、跨日和取消；
并发/嵌套子代理及权限/提问；父回复先结束；刷新/断线/会话身份切换；取消后已有消费；
账号/工作区切换；同一请求集合的前端精确值与 Fusion 汇总逐项相等。
上述产品入口验证和客户端 Rust 编译未执行前，不能宣称终端与前端已全量验收一致。
