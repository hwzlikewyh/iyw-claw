# 会话输出图片原生上下文

## 问题与目标

执行工具返回本地预览路径后，模型原来还需调用一次 view_image 才能看到图片。
当前会话受管 output 图片应随原工具结果进入下一次模型请求，复用现有原生视觉输入，
避免额外模型往返。

## 范围

- 仅识别工具结果明确引用的
  chat-sessions/<date>/<uuid>/output 图片，不扫描目录。
- 接入直接 exec_command、write_stdin 轮询和 MCP 结果；远程环境与普通工作区
  文件不自动读取。Code Mode 的嵌套工具保留显式转发媒体的既有行为。
- 每个工具结果最多八张图，累计原始文件不超过 16 MiB。读取前检查文件类型、
  归属和大小；流式累计字节再次限额，拒绝检查时已存在的符号链接和越界路径。
- Windows 路径使用既有 dunce 规范化，兼容常规盘符和系统返回的扩展路径前缀。

## 数据流

工具结果中的受管路径先转为原生 InputImage，再由既有 image preparation
执行图片准备并提交给本地网关。本地网关向 Fusion 请求上传票据，将图片字节直接
PUT 到 TOS，回报完成状态，再返回受管 file_id。图片正文不经云端 Fusion 上传。

模型请求携带图片引用经过 Fusion，云端继续承担鉴权、资源所有权校验、路由和计费。
上游支持图片 URL 时直接读取 TOS；不支持 URL 时，既有云端内联兼容分支仍需读取
并转发图片字节。

MCP 原始结果、artifact 通知和 hook 元数据保持既有路径。模型结果同时保留
结构化文本和图片；新增附件不写入原始工具日志，不触发额外生成或自动重试。

## 压缩恢复

普通压缩从其历史快照收集图片，远程压缩从本次 prompt_input 收集图片，
避免后台前缀压缩误取后续新消息。已保留的原生图片不重复附加。

缺失图片以 ImageReference::File 恢复，不注入 view_image 重读指令。
恢复沿用既有 64,000 token 保留预算，扣除已有保留内容及说明文字预留量，
优先选择最近的图片，再保持原首次出现顺序。恢复消息标记为 compaction.summary，
不充当新的用户授权。旧摘要中的受管图片 ID 可迁移；普通文本提到的 ID 不自动转图。

## 验收与验证边界

1. 直接命令或后续轮询返回当前受管 output 图片时，结果含原生图片块和文字。
2. MCP 同时含 structuredContent 与 Image 时，两者都进入模型上下文。
3. 压缩恢复使用原生受管引用，去重并遵守既有上下文预算。
4. 任意工作区、其它会话、远程环境和超限图片不被自动上传。
5. 继续使用现有 TOS 直传；日志不含图片内容、签名 URL 或凭证。

按仓库规则只进行调用链静态审查、Rust 语法/格式解析及 git diff --check，
不新增或运行测试，不在本机编译、启动或打包桌面应用。
真实星河端到端验证尚需安装相应构建，确认同一预览无额外 view_image 往返，
并核对本地网关的 TOS 直传及模型请求日志。
