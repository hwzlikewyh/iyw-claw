# 定时任务工作台

定时任务主页使用卡片布局，执行记录集中在“运行记录”和单个任务详情中，首页不展示“最近执行”。

## 页面与交互

- 任务卡片展示名称、智能体、内容摘要、工作目录、执行计划、下次运行时间、通知渠道和最近状态。支持搜索、目录筛选、启停、立即运行、编辑和通知设置。
- 点击任务进入该任务的执行时间线，再从具体记录打开应用原有聊天标签。聊天所在目录和智能体从该次会话读取，不依赖任务后来修改的配置。
- 全局运行记录按任务名称、工作目录、状态、触发方式和任务筛选，每页 50 条。保留原有 30 天清理策略。
- 启动失败或已跳过的记录可能没有聊天，界面明确显示“未创建聊天”。运行中的记录保留取消入口。
- 新建沿用现有模板流程；编辑沿用 RichComposer、引用、命令、技能、动态智能体／模型配置、默认任务目录和结构化计划，采用内容与计划／通知两栏布局。

## 补跑

失败记录（含重启中断）可补跑。补跑创建新的执行，记录 `retry_of_run_id`，不修改原状态，也不改变下一次定时计划。补跑使用当前任务配置，并沿用现有执行引擎与同任务并发保护。

已有成功或正在执行的补跑时，原记录显示关联入口；关联不受当前列表分页和筛选影响。没有聊天的关联记录可查看其状态和错误摘要。

批量入口选择当前页的失败记录，最多 50 条，进入数据库元数据中的持久队列。同一个任务的上次运行未结束时等待，进程重启后继续处理。启动前再次检查任务有效性、失败状态及已有补跑，避免重复执行。

## 完成通知

每个任务在 `config.notification_channel_id` 保存一个具体对话渠道实例 ID；空值表示关闭通知。渠道来自已有渠道设置，显示连接状态并提供管理入口。

每次执行在创建时保存通知渠道、显示名和接收目标快照。执行结束后发送状态、结果摘要、执行编号与应用内查看位置。通知文案遵循已有 `chat_message_language` 设置，结果正文保留任务输出的语言。

发送复用渠道管理器、已登记目标和消息日志。普通完成、启动失败、取消、重启中断都进入通知处理；跳过不通知。通知失败不影响任务执行结果。

通知状态包括 `pending`、`sending`、`sent`、`queued`、`failed`。使用数据库条件更新领取发送权；发送超时或处理中断标记结果未知并停止自动重发，以免外部平台重复发送。渠道延迟投递显示排队状态，不标记为已发送。

## 数据与接口

新增迁移 `m20261016_000001_automation_delivery` 为 `automation_run` 添加补跑来源、通知快照、发送状态和时间，旧记录保持空值；任务通知配置利用原有 JSON 配置列，不新增依赖。

新增桌面命令和同名 POST 接口：

| 命令 | 参数 | 返回 |
| --- | --- | --- |
| `automation_run_history` | `query`，含可选任务、目录、状态、来源、关键词、偏移量和 `retryable` | `runs`、`total` |
| `automation_get_run` | `runId` | 具体执行及补跑关联 |
| `automation_retry_run` | `runId` | 新执行 ID |
| `automation_retry_runs` | `runIds` | 新入队数量 |

查询和批量执行共享 core/service，桌面与服务器遵循同一行为。页面继续使用 AutomationsViewProvider、`automation://changed` 事件及重连补取。
