# 星河内部 MCP 与模型确认

日期：2026-11-02。

## 行为

星河核心已链接进主进程，内置工具现在复用内核已有的进程内 MCP 工厂，
不经过本机 TCP、HTTP、SSE，也不发送 HTTP 会话 DELETE。
MCP 消息仍需编码，以衔接应用 rmcp 1.3.0 和内核 rmcp 3.5.1。
未测量端到端延迟，不承诺模型响应速度变化。

宿主在正常启动、预热和恢复时注入连接工厂。内核只对精确登记端点和本地环境
使用该工厂；凭证必须由宿主提供。应用校验有效会话 token、星河身份、
连接归属与工具命名空间。预热 runtime 在首次有效连接时绑定归属，后续不可换主。
授权仍由正常会话生命周期签发与撤销，不通过任意 localhost URL 或工具参数授权。

内存流缓冲 64 KiB，每条入站消息上限 32 MiB，每连接最多 256 个未完成请求，
每个父连接最多 64 个协议连接。结果完整写入后才提交投递回调；失败、取消或
丢弃会中止对应回执。关闭、恢复和父会话撤销负责取消并回收连接任务。
任务等待不持有全局父连接表锁，避免影响其他会话清理。

## HTTP 与其他 SDK

其他 Agent SDK 继续通过原 Streamable HTTP `/mcp` 接入，保留：

- loopback Host/Origin 校验、Bearer 认证及协议会话与授权主体绑定；
- 初始化、POST 调用、GET 事件流、DELETE 清理和请求体大小限制；
- 每个协议连接独立订阅工具目录变化；
- 现有工具实现、会话能力检查、取消预算、反馈回执和宿主兜底回收；
- 启动环境现有的 `NO_PROXY` / `no_proxy` 本机地址配置。

HTTP 与内存流使用同一 `BuiltinMcpHandler`，仅可信上下文的注入位置不同。
外部 MCP、远程环境、模型网关和真正的云端请求继续沿原有路径运行。
因此该修改只解除内置 MCP 通道对应用网络策略的传输依赖，不能解决
配置加载失败或模型/远程服务的所有网络故障。

## 模型切换

“所选模型应用失败”原来可能由模型应用成功后的会话记录保存失败触发。
现在保存失败独立记录，不再误报模型切换失败。
重连后目标出现在目录但仍等待切换确认时，等待正常设置请求或原有截止时间，
不因中间选值提前失败。同一连接/配置/目标的在途同步去重；旧连接的排队请求
和迟到结果不能修改新连接，旧目标的回调不能覆盖当前选择。
真正的切换拒绝或超时继续保留失败和发送门禁，不自动改用其他模型。
