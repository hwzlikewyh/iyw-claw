# 图片 MCP 的传输、并发与模型选择

`generate_iyw_image` 优先使用适用的平台功能；复杂、多重视觉约束或需要更自由控制的任务
使用图片模型。普通文生图可以使用 `micro-generate`，改款、系列延伸、多图融合分别使用
`variation`、`extend`、`mix`。选择 Fusion 图片模型时，无图用 `generate`，有图用 `edit`。

## 平台模型选择

平台“模型一／二／三”分别对应 `parameters.modelChannel=1/2/3`，不是 Fusion 目录顺序。
`variation/extend/mix` 保留显式通道，省略时才默认 2；误用 `parameters.model` 会在预检拒绝。
用户锁定模型时，不自行添加其他模型回退。A+ 编辑等固定通道操作保持各自契约。

```json
{
  "type": "variation",
  "prompt": "保留原图主体，改款为东方中式风格",
  "images": ["https://example.com/source.png"],
  "parameters": {"modelChannel": 1}
}
```

`metadata.requested_model_channel` 记录提交的通道选择，批量及回退轨迹保留该字段。
它说明请求参数，不单独证明上游最终执行的内部模型。

## URL 与素材准备

图片模型编辑通过 JSON `images[].image_url` 提交参考图，蒙版使用 `mask.image_url`。
本地路径、Data URL 和 Base64 先由主机校验并上传取得 HTTPS URL；生成请求不发送图片文件。
普通 HTTPS 输入直接提交，内容、格式及大小由上游校验。蒙版编辑仅读取蒙版与首张参考图
检查 PNG／尺寸，读取沿用项目已有的有限流下载、地址校验及单图 20 MiB 限制。

同次调用内合并相同来源的准备和相同内容的上传；完成后只保留 URL、MIME、尺寸及字节数，
释放原图与已用的编码输入。来源顺序及角色保持独立，输入和输出 URL 保留签名 query。
模型声明的参数、数量、格式和已知输入大小限制继续在预检及提交前校验，不依赖原图驻留。

## 并发与缓存

- 每批最多 64 项、16 路生成请求并发，输入准备另有 16 路；不同调用独立，不增设全局门槛。
- 全批静态参数、路线和模型预检完成后，各项准备好即提交，不等待整批输入。
- 生成许可只覆盖提交和响应读取，轮询、退避和结果处理不占名额。
- 单项输入失败只影响该项，其他项继续；最终按输入顺序汇总。
- 模型列表与生成共享按账号／工作空间隔离的 60 秒目录缓存；调用时检查时间，过期才查询。
  不使用定时器或后台刷新。并发刷新合并，失败不跨调用缓存；缺失引用在提交前最多刷新一次。
  账号／空间变化阻止旧上下文继续复用，服务端仍执行每次提交的鉴权及路由校验。

## 取消与失败恢复

排队、素材准备、请求等待、轮询和退避响应取消。已提交的远程任务不保证被取消，结果未知
时不能盲目重提；保留已知任务编号及图片。只读状态查询的短暂网络失败或 429／503 最多额外
恢复两次（1／2 秒），每次请求不超过剩余 wait 预算及 30 秒，不重新提交生成。

已确认的生成输出下载／转存 502 沿用最多三次额外重提（2／4／8 秒），每次可能产生费用。
普通 502、超时或未知状态不进入该重试。部分结果处理失败时保留成功图片并返回 `partial`，
安全详情见 `metadata.output_errors`；结果处理全部失败不自动重新生成。

## 交付验证

本次在独立工作区基于远程 `main` 集成，保留其模型能力投影及参数校验；大小校验改读素材
元数据，避免为校验保留图片字节。运行 Rust 格式／语法解析、定向 diff、文档 JSON 和静态
调用链检查。依仓库规则未运行编译、测试或真实收费生图，也未实测性能倍数。
