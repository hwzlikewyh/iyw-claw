# ACP 会话预准备

## 目标与边界

星河与远山使用现有 ConnectionManager 提前完成原生新建/恢复、必需 MCP 目录和模型/模式确认。
用户打开时优先接管已经就绪的同一连接，命中路径目标是完整就绪 P95 不超过 200ms。
冷启动、未提前准备的历史及配置失效后的回退仍需正常启动；本次没有端到端实测证明全部场景达标。

其他 Agent 保留公共 ACP 连接复用、技能遍历和探测收尾优化；会话预准备当前仅对
`codex`、`claude_code` 开启，没有假设其他适配器具备相同恢复生命周期。

## 使用路径

- 历史侧栏项和非活动标签悬停或聚焦 150ms 后，提前请求恢复；离开前尚未触发的请求会取消。
- 当前已保存会话真正就绪后，准备一个相同 Agent 的新会话。项目会话使用当前工作目录，
  无项目聊天分配独立 scratch 目录。用户新建聊天时该目录只允许领取一次。
- 准备不创建应用对话记录、不发送 prompt。既有原生初始化、MCP 握手与会话存储照常执行。
- 原生会话、MCP 和选择器全部就绪才允许接管。用户提前点击时等待正在进行的准备，不伪造 ready。
- 未命中、过期或配置变化时沿原入口回退；同一历史必须先等待被取消的准备连接释放。

## 生命周期

最多两个准备任务/未使用的就绪会话，正在清理的实例也占名额。有效期 120 秒，前端在
110 秒释放本地句柄。内存紧张或存储迁移时不创建新准备任务；配置失效、窗口关闭和应用退出
均取消准备。任务由既有 ConnectionTaskRegistry 跟踪，退出时统一收尾。

准备阶段通过 EventEmitter 的共享激活标记抑制外部事件；SessionState 仍正常更新并保存事件环。
普通发现、复用和连接列表不暴露未接管实例，实际发送入口拒绝尚未接管的连接。
接管在池锁内只执行一次，激活原事件目标并补发 SessionStarted，前端沿既有快照附着流程同步状态。

接管重新读取当前账号、有效环境、运行时版本、策略代际、MCP 配置、技能启用策略和相关设置。
同时比较项目/全局指令文件与 Skill 入口的元数据。目标、模式、模型和响应风格必须匹配。
这些检查失败时取消准备，不跳过认证、权限或模型确认来追求耗时。

仅删除本次分配、未领取且确实为空的 scratch 目录。已领取目录由既有草稿管理负责；原生初始化
在目录中留下文件时交给既有 orphan scratch GC，不递归删除用户或 Agent 已产生的文件。
这里没有新增原生 worker 共享、数据库 schema 或快照持久化格式。

## 接口与日志

桌面 Tauri 命令和服务器 POST 路由保持一致：

- `acp_prepare_session`：提交目标及当前偏好，返回准备句柄与工作目录；资源不足时返回 null。
- `acp_cancel_prepared_session`：取消尚未接管的准备，不影响已接管连接。
- `acp_reserve_prepared_workspace`：一次性领取新聊天的准备目录。
- `acp_connect`：自动尝试匹配准备结果，原有调用参数保持兼容。

`[ACP][prepare]` 记录 started、ready、失效、claim completed、retired。
`[ACP][startup] stage=prepared_session_lookup` 的 ready/miss 和 since_accepted_ms
可用于区分接管路径与冷启动。准备耗时不等同于点击后耗时；首次模型响应需继续单独统计。
日志不记录凭证、完整配置或对话正文。
