# 聊天图片格式

聊天附件的文件选择、粘贴、拖拽、工作区路径和重新上传共用源格式识别。
源文件保持原样；发给模型的内容仍使用 PNG、JPEG、GIF 或 WebP。

| 源格式 | 处理方式 |
| --- | --- |
| PNG/APNG、JPEG、GIF、WebP | 保留原字节，不缩放或有损重编码 |
| JPEG 后缀 `jpg/jpeg/jfif/jpe/jif/jfi/pjpeg/pjp` | 归一化为 `image/jpeg` |
| BMP、TIFF/BigTIFF、ICO/CUR、TGA、PNM/PBM/PGM/PPM/PAM、QOI、DDS | 后端使用已有 image 库的解码器，生成 PNG 副本 |
| HEIC/HEIF/HIF | 后端使用 heic-decoder 解码，处理容器旋转、裁剪和透明度，再生成 PNG；有 ICC 时嵌入 PNG |
| SVG | 后端使用 resvg 渲染为 PNG；只接受自包含图片，不读取外部引用 |
| AVIF | 客户端使用目标浏览器的解码能力生成 PNG，再复用原有上传流程 |

后缀和 MIME 的常见别名在图片格式模块中集中管理，大小写不敏感。
桌面分块上传也接受已声明有效图片 MIME 的未知后缀，最终按真实文件内容准备图片。
已知后缀与已声明格式明显冲突时仍会拒绝，不依赖改名跳过内容校验。

多页 TIFF 和 HEIF 序列取第一张图片；ICO/CUR 按解码器规则选择图像。
AVIF 的静态图像或序列首帧由浏览器解码。已有 GIF/APNG/WebP 保留原数据，
最终模型如何处理动画由其自身能力决定，不代表逐帧识别。

## 限制与错误

- 图片源文件上限为 100 MiB，供模型使用的原图或转换结果上限为 32 MiB。
- 单边上限为 16384 像素。后端的额外格式在解码前按像素数、位深和转换内存检查，
  超过解码预算时明确拒绝；PNG 编码输出也受限。AVIF 由浏览器解码，应用取得位图后
  检查尺寸和内存，解码期间也受浏览器自身的资源限制。
- AVIF 路径转换复用原有 `read_file_base64`，其读取上限为 100,000,000 字节。
  它与浏览器直接选择文件的 100 MiB 源上限略有差异。
- 新格式的 PNG 可能明显大于源文件，超过 32 MiB 时需要用户先缩小图片。
- HDR 色调映射、专业 RAW/PSD、所有 HEVC 特殊编码和 SVG 外部资源不在支持承诺内。
  无法识别或解码时会显示具体格式/处理错误，不静默当成识图成功。
- HEIC/HEIF 的解码库与浏览器的 AVIF 实现各有编码限制；编译通过不能替代各平台真实图片验收。

## 实现与验证边界

后端源格式准备位于 `src-tauri/src/commands/chat_image/`，输出进入原有受管存储、
图片资源准备和模型网关。前端的源格式模块位于 `src/lib/chat-image-formats.ts`，
AVIF 转换按需加载，路径读取保持对应本地/工作区 transport 与上传权限检查。

本次不新增 HTTP 接口、共享 schema 或测试文件。按仓库约定进行静态调用链审查、
TypeScript/ESLint 和 Rust 编译检查；真实桌面/Web 上传、Win7 及 macOS/Linux 的
图片样本验收、完整打包和安装版行为仍需单独验证。
