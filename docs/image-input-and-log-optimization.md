# 图片原生输入与重复开销优化

2026-10-20。依据最近日志与真实会话复核，修正星河附件入口并减少重复历史读取及日志量。
本次为源码变更，尚未进行桌面端到端验收或发布。

## 图片路径

星河附件先校验受管文件、MIME、大小、会话归属和上传权限，再从已校验的本地文件
构建原生 image 内容块。首次模型输入直接包含图片，不再仅发送路径并等模型调用
view_image。显式读取工作区图片和压缩后重新查看图片仍可使用原有工具。

附件准备沿用 images/input/prepare 的 lookup/upload 契约，但地址改为当前主进程
模型网关。未命中时，由已有本地转换执行 init、PC 直传对象存储、complete。
本地网关未就绪、资源准备失败或模型未启用资源能力时明确返回错误，不再因资源
接口不可用而转到旧上传链路。连接池复用；loopback 请求不使用系统代理、不跟随重定向。
云端仍负责 token 鉴权、资源所有权、渠道路由和计费。

模型历史继续保存受管图片引用；界面回放保留原附件输入。当前历史解析器不能展示
受管 file_id，所以跳过对应 response_item 的无图副本，使用后续 user_message 中
的图片恢复界面，避免重复用户消息或历史图片消失。没有改写已有会话文件。

## 历史与用量

- 用量读取复用历史页请求，不再同时读取、反序列化和合并含附件的输入队列。
- 相同参数的强制刷新在同一微任务内合并；读取期间收到的新状态最多安排一次
  后续补读，后续补读期间仍可继续接收更新；失败也释放在途状态。
- 用量首屏仍强制核对最新状态，更早分页读取缓存；核对会话、回合边界、总条数、
  transcript 水位及累计 token 快照。不一致时返回不完整状态，交给原有有限重试补读。
- 缓存分页的确认金额先清除，再应用本次首屏核对的权威账单，避免复用旧账号金额。
- 工具状态完成本身不触发账单重读，继续由 usage_update、模型消息和回合终态驱动。

本轮没有新增接口或持久缓存。每次首屏强制刷新仍可能解析完整历史，尚未实现独立
的轻量用量接口或所有解析器的增量历史读取。

合入主分支时保留最新的账号代际隔离、权威账单字段与账单/委派事件刷新，输入队列
的在途合并也按账号代际隔离，不跨账号复用请求。

## 日志

主进程默认过滤 codex_otel.log_only 的 info/debug/trace 记录，保留该 target 的
警告和错误；trace_safe、实际工具记录、usage 与终态日志继续沿原有设置记录。
独立过滤层同时受全局日志设置约束，不重新开启 off/error 已关闭的记录。

需要诊断逐碎片遥测时，可以在既有 IYW_CLAW_LOG/RUST_LOG 指令里显式设置
`codex_otel.log_only=debug`；该设置仅用于按需排障，不修改用户当前环境。

图片准备记录原始请求字节、图片大小、是否实际直传和准备耗时；仅在请求体被缩小
时以 info 记录转换前后字节。日志不包含图片、原始 payload、令牌、签名链接或随机路径。
这些是局部请求证据，不能直接换算成 Fusion 整体带宽降幅。
